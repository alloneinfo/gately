# 감사 로그와 설정 기록

Gately는 DNS 키와 인증서 개인 키를 다루므로 누가 언제 무엇을 했는지, 설정이 어떻게 바뀌었는지 추적하고 되돌릴 수 있어야 합니다.

## 감사 로그

사이드바 「시스템 → 감사 로그」에 다음 작업이 최신순으로 표시됩니다. 분류로 필터링하거나 경로, 사용자, IP로 검색할 수 있습니다.

| 분류 | 기록 내용 |
| --- | --- |
| 로그인 | 비밀번호, 패스키, 서드파티 로그인의 성공과 실패, 로그아웃 |
| 변경 | 관리 콘솔과 API 토큰이 수행한 모든 쓰기 작업(추가, 수정, 삭제, 시작/중지, 되돌리기 등) |
| 민감 접근 | 설정 백업, 진단 번들, 인증서 개인 키 다운로드, 웹 터미널 또는 컨테이너 터미널 열기 등 |

각 기록에는 시간, 작업자(사용자 이름 또는 `api-token:<토큰 이름>`), 출처 IP, 메서드, 경로, 상태 코드가 포함됩니다. **요청 본문과 비밀 값은 기록하지 않습니다**.

- 로그는 설정 디렉터리의 `audit.log`(JSON Lines)에 기록되며, 파일이 5 MiB를 넘으면 순환하고 이전 파일 3개를 보관합니다.
- 관리 UI를 이 호스트의 리버스 프록시 뒤에 두면 실제 출처를 기록하고 거쳐 온 프록시 주소를 따로 표시합니다. 원리는 [보안 모델](/ko/docs/guide/security)을 참고하세요.
- 변경과 민감 접근은 `audit.change`, `audit.access` 이벤트로 발행되며 [알림 센터](/ko/docs/modules/notify)에서 「설정 변경」, 「보안 및 로그인」 템플릿으로 푸시할 수 있습니다.
- 읽기 전용 계정과 API 토큰은 감사 로그를 볼 수 없습니다.

## 설정 기록과 되돌리기

설정 파일을 덮어쓰기 전마다 Gately는 이전 내용을 하나의 기록 버전으로 설정 디렉터리의 `history/<이름>/`에 저장하며, 설정마다 최근 30개를 보관합니다. `account.json`(계정 자격 증명)과 `tokens.json`(토큰)은 기록하지 않습니다.

「시스템 → 설정 기록」에서:

1. 설정 파일을 선택해 각 버전의 저장 시각과 크기를 확인합니다.
2. 「비교」를 눌러 해당 버전과 현재 설정의 줄 단위 차이를 봅니다.
3. 「되돌리기」를 눌러 해당 버전을 복원합니다. 적용을 위해 Gately가 자동으로 재시작됩니다.

되돌리기 직전의 현재 내용도 새 기록 버전으로 저장되므로 되돌리기 자체도 다시 취소할 수 있습니다.
