# Tailscale / frp / cloudflared

세 모듈은 공식 프로그램을 프로세스로 관리하는 방식으로 통합되어 있습니다. 자동 재시작, 로그의 UI 집계, UI에서의 설정을 지원합니다. Gately 본체에는 이 프로그램들이 내장되어 있지 않으므로 항상 업스트림 최신 버전을 사용할 수 있습니다.

## 프로그램 배치

다음 순서로 실행 파일을 찾습니다.

1. 모듈 설정에 입력한 경로
2. `PATH`
3. 설정 디렉터리 아래의 `bin/` 하위 디렉터리

Docker로 배포할 때는 마운트한 설정 디렉터리에 바이너리를 넣으면 됩니다. 예: `./gately-data/bin/frpc`. Tailscale은 `tailscale`과 `tailscaled`가 모두 필요합니다.

토큰과 키는 0600 권한으로 저장되며 cloudflared의 토큰은 환경 변수로 전달되어 프로세스 목록에 나타나지 않습니다.

## Tailscale

- `tailscaled`를 관리하거나(사용자 공간 네트워킹, 컨테이너 친화적) 시스템에 이미 있는 데몬에 연결합니다.
- 인증 키 또는 로그인 링크를 사용하며 Headscale을 지원합니다.
- 서브넷 라우트와 출구 노드
- 노드 목록과 SOCKS5 프록시
- WireGuard UDP 포트 고정: 방화벽에서 직접 연결을 허용하기 쉽습니다.
- tailscaled 추가 인자와 환경 변수. 호스트 iptables가 nf_tables 백엔드라면 환경 변수에 `TS_DEBUG_FIREWALL_MODE=nftables`를 추가해야 서브넷 포워딩이 동작합니다.

## frp

- **frpc 클라이언트**: tcp / udp / http / https / stcp / xtcp 프록시를 추가하거나 삭제하면 바로 적용됩니다.
- **frps 서버**: 포트 허용 목록, 서브도메인, 대시보드
- **기존 설정 가져오기**: 페이지 상단의 「설정 가져오기」는 이전 버전의 `frpc.ini` / `frps.ini`(`[common]` 섹션 포함)와 frp 0.52+의 `toml`을 지원하며 파일을 선택하거나 내용을 붙여 넣을 수 있습니다. 먼저 파싱 결과와 무시된 필드를 미리 본 뒤 가져오기를 확정합니다. 클라이언트는 추가(같은 이름의 프록시는 그대로 유지) 또는 모든 프록시 교체 중에서 선택할 수 있습니다. 가져와도 사용 상태는 바뀌지 않으며 `POST /api/frp/import` 엔드포인트로도 호출할 수 있습니다.
- **Lucky에서 마이그레이션**: `lucky_frp.lkcf`의 첫 번째 클라이언트 인스턴스와 첫 번째 서버 인스턴스를 바로 가져올 수 있습니다. [Lucky에서 마이그레이션](/ko/docs/guide/migration)을 참고하세요.

## Cloudflare 터널

- 토큰 터널과 trycloudflare 임시 터널
- 다중 터널, 자동 재시작
- 공인 주소 표시
- 터널 토큰을 사용하는 터널은 Lucky에서 가져올 수 있습니다.

## 선택 기준

| 상황 | 권장 |
| --- | --- |
| 여러 기기 사이에 프라이빗 네트워크를 구성 | Tailscale |
| 공인 서버가 있고 내부 서비스를 외부로 매핑 | frp |
| 공인 IP도 서버도 없이 웹 서비스를 빠르게 공개 | Cloudflare 터널 |
| 통신사가 홀 펀칭 가능한 NAT를 제공 | [STUN 통과](/ko/docs/modules/stun) |
