# 포트 포워딩

이 호스트에서 수신하는 포트를 다른 장치나 서비스로 전달합니다.

## 기능

- TCP와 UDP
- IPv4와 IPv6, v4 / v6 간 상호 포워딩
- 포트 범위와 다중 포트
- 다중 대상과 장애 조치
- 연결 수 제한
- 트래픽 통계와 실행 로그
- 대상에 PROXY 프로토콜(v1 / v2)을 보내 실제 클라이언트 주소를 하위 단계에 전달

## PROXY 프로토콜

포트 포워딩은 TCP 중계만 하므로 하위 서비스에는 기본적으로 Gately 자신의 주소만 보입니다. 규칙에서 「PROXY 프로토콜」을 v1 또는 v2로 설정하면 Gately가 대상에 연결한 뒤 PROXY 헤더를 먼저 보내므로, 하위 서비스가 실제 클라이언트 주소를 얻어 로그, 속도 제한, 접근 제어에 활용할 수 있습니다.

대상에서 해당 수신 옵션을 켜야 하며, 그렇지 않으면 연결이 거부됩니다. 예:

- haproxy: `bind 192.168.1.8:4434 accept-proxy`
- nginx: `listen 4435 ssl proxy_protocol;`
- Gately 웹 서비스: 리스너에서 「PROXY 프로토콜 수신」을 켜고 출처를 신뢰할 PROXY 출처에 추가합니다.

이 옵션은 TCP에만 적용되며 UDP 포워딩에는 영향을 주지 않습니다.

## 대표 사용 사례

- NAS의 서비스 포트를 하나의 진입점으로 노출
- IPv6와 IPv4 사이의 상호 연결 포워딩
- 서비스 하나에 주/예비 백엔드 두 개 구성

## 배포 팁

포트 포워딩은 호스트 포트를 직접 수신하므로 Docker 배포에서는 `--network host`를 권장합니다.

## Lucky에서 마이그레이션

규칙은 `lucky_portforward.lkcf`에서 가져올 수 있습니다. TLS / 스트림 암호화와 속도 제한 등의 옵션은 아직 지원하지 않으며 가져올 때 안내가 표시됩니다.
