# Gately v0.5.3 출시

2026년 10월 21일

이번 릴리스의 중심은 fnOS입니다. 이제 Gately를 fnOS 네이티브 앱으로 설치할 수 있습니다. fnOS 바탕 화면 아이콘으로 열고, fnOS에 이미 쓰고 있는 진입점을 그대로 사용하며, fnOS 관리자는 다시 로그인할 필요가 없습니다. 쓰지 않는 기능 모듈은 통째로 끌 수도 있습니다.

[v0.5.3 다운로드](/ko/download#fnos) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.3)

## fnOS 네이티브 앱

모든 릴리스에 fnOS 오프라인 패키지 `gately_0.5.3_fnos_x86.fpk`(Intel / AMD)와 `gately_0.5.3_fnos_arm.fpk`(ARM)가 포함됩니다. fnOS의 「앱 센터 → 수동 설치」에서 설치하세요.

- **fnOS 통합 게이트웨이 연동**: 바탕 화면 아이콘을 클릭하면 관리 UI가 `/app/gately/` 아래에서 열리며 fnOS와 같은 진입점을 씁니다. 내부망 주소와 fnOS 원격 도메인 모두 사용할 수 있고 16680 포트를 열거나 포워딩할 필요가 없습니다. 게이트웨이를 통한 접근은 fnOS가 제어하며 fnOS 관리자만 열 수 있습니다.
- **fnOS 관리자 로그인 상태로 로그인**: 「설정 → 접근 제어」에서 「fnOS 로그인 상태로 자동 로그인」을 켜면 fnOS에 이미 로그인한 관리자는 비밀번호나 2단계 인증 코드 없이 바로 Gately에 들어갑니다. 일반 fnOS 사용자는 계속 로그인해야 합니다. 로그아웃한 뒤에는 조용히 다시 로그인시키지 않고 로그인 페이지에 「fnOS 계정 &lt;이름&gt;(으)로 로그인」 버튼을 표시합니다. 이 설정은 기본적으로 꺼져 있습니다.
- **모든 기능 사용**: 앱이 root로 실행되므로 80/443을 수신하고 Docker를 관리하며 웹 터미널을 열 수 있습니다. 제거해도 설정은 유지되며, 업그레이드는 새 버전의 `.fpk`를 설치하면 됩니다.

자세한 내용은 [설치 및 배포 · fnOS 네이티브 앱](/ko/docs/guide/install#fnos)을 참고하세요.

## 기능 모듈 스위치

「설정 → 기능 모듈」에서 모듈 전체를 끌 수 있습니다. 비활성화된 모듈은 설정은 불러오지만 서비스를 시작하지 않고 관리 API도 제공하지 않으며(엔드포인트는 403 반환) 화면에서 숨겨집니다. 설정은 유지되며 다시 켜면 복원됩니다. 다른 모듈이 의존하는 모듈은 끌 수 없고, 변경 사항은 재시작 후 적용됩니다. 몇 가지 기능만 쓴다면 수신하는 서비스와 호출할 수 있는 엔드포인트를 줄일 수 있습니다.

## 기타 개선

- 관리 UI가 언어별 번역을 파일 하나로 묶어 첫 로딩 요청 수가 약 170개에서 약 75개로 줄었습니다. 지연 로딩하는 페이지나 스타일시트를 불러오지 못하면 한 번 자동으로 새로 고칩니다.
- API 문서에 모듈 스위치와 fnOS 관련 설정 필드 설명을 추가했습니다.

## 업그레이드

- Docker: 새 이미지를 받은 뒤 컨테이너를 다시 만듭니다. 바이너리: 실행 파일을 교체한 뒤 재시작합니다.
- fnOS 네이티브 앱과 Docker 이미지는 모두 16680 포트를 사용합니다. Docker 이미지에서 네이티브 앱으로 옮기기 전에 `gately` 컨테이너를 멈추고 설정 디렉터리를 앱의 `var/config`로 복사하세요.
