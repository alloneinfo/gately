# Gately v0.5.8.1 출시

2026년 10월 26일

v0.5.8 계열의 기능 업데이트로, [issue #18](https://github.com/wangwanjie/gately/issues/18), [#19](https://github.com/wangwanjie/gately/issues/19), [#20](https://github.com/wangwanjie/gately/issues/20), [#22](https://github.com/wangwanjie/gately/issues/22)의 제안을 바탕으로 했습니다.

[v0.5.8.1 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.8.1)

## 파일 서비스 공유 사용자

WebDAV, FTP, SMB가 하나의 "공유 사용자" 목록을 함께 써서 비밀번호와 디렉터리를 한 번만 관리하면 됩니다. 세 서비스 페이지 모두에 "공유 사용자" 카드가 있으며 어느 페이지에서 바꿔도 함께 적용됩니다. 공유 사용자 허용 여부는 서비스마다 스위치로 정하고, 기존 로컬 사용자는 그대로 쓸 수 있으며 이름이 같으면 로컬 사용자가 우선합니다. 공유 사용자만으로 서비스를 켤 수도 있습니다. 변경 후 WebDAV는 다음 요청부터 새 설정으로 인증하고, FTP는 로그인된 세션을 끊으며, SMB는 계정이 바뀌면 다시 불러옵니다. 자세한 내용은 [파일 서비스](/ko/docs/modules/tools#shared-users)를 참고하세요.

## 연결 끊기 사이트와 접근 로그

사이트 유형에 "연결 끊기"가 추가되었습니다. 아무것도 보내지 않고 연결을 끊으며 nginx의 `return 444`와 같습니다. 기본 사이트로 두면 알 수 없는 도메인을 스캔하는 요청에 아무 응답도 하지 않고, 접근 로그에는 444로 기록됩니다. nginx 설정을 가져올 때 `return 444`는 이 유형으로 변환됩니다.

웹 서비스 접근 로그 끝에 nginx combined 형식으로 Referer와 User-Agent가 붙어, 같은 공인 IP 뒤의 기기를 구분할 수 있습니다. 자세한 내용은 [웹 서비스](/ko/docs/modules/web)를 참고하세요.

## frps 수신 대기 주소

frps는 frpc 연결 포트와 프록시 포트(HTTP, HTTPS, tcp/udp 프록시의 원격 포트)의 수신 대기 주소를 각각 지정할 수 있으며, 비워 두면 모든 주소입니다. 예를 들어 frps를 127.0.0.1에서만 수신 대기하게 하고 Gately 사이트가 websocket이나 wss로 전달하게 할 수 있습니다. 자세한 내용은 [터널](/ko/docs/modules/tunnels)을 참고하세요.

## 복사 버튼과 2단계 인증

HTTP로 관리 화면을 열면 브라우저가 클립보드 API를 제공하지 않으므로, 이제 복사 버튼이 자동으로 호환 방식을 사용합니다. 그래도 실패하면 텍스트를 선택하고 직접 복사하라고 안내합니다. 2단계 인증 입력란은 Bitwarden 등 비밀번호 관리자가 인식해 코드를 자동으로 채울 수 있습니다.

## 업그레이드 안내

- 공유 사용자를 바꾸려면 API 토큰에 `webdav:write`, `ftp:write`, `smb:write`가 모두 필요합니다. 공유 사용자만으로 켠 서비스는 공유 사용자를 모두 지울 수 없습니다.
- "연결 끊기" 사이트는 인증, 접근 제어, WAF를 거치지 않으며 사이트의 다른 설정은 적용되지 않습니다.
- 접근 로그에서 너무 긴 URI, Referer, User-Agent는 잘립니다.
