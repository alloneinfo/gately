# Gately v0.5.8 출시

2026년 10월 25일

이번 버전에서 Gately는 OIDC ID 공급자로 동작할 수 있게 되었고, SMB 파일 공유를 추가했으며([#15](https://github.com/wangwanjie/gately/issues/15)), 모든 로그에 필터를 더하고([#16](https://github.com/wangwanjie/gately/issues/16)), WAF 규칙 그룹의 순서를 조정할 수 있게 했습니다([#17](https://github.com/wangwanjie/gately/issues/17)).

[v0.5.8 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.8) · [OIDC 통합 로그인 문서](/ko/docs/modules/oidc)

## OIDC 통합 로그인

Web 서비스에 OpenID Connect ID 공급자가 내장되었습니다. Gitea, OpenList, Grafana 등 OIDC 로그인을 지원하는 앱은 공유 사용자로 바로 로그인할 수 있고 누가 로그인했는지도 구분할 수 있어, Authelia의 OIDC 기능을 대신할 수 있습니다.

- 「Web 서비스 → 전역 설정 → OIDC ID 공급자」에서 발급자 주소를 입력하고 클라이언트를 추가하면 되며, 발급자 도메인용 사이트는 만들 필요가 없습니다;
- 공유 사용자에 선택 사항인 이메일, 표시 이름, 그룹이 추가되었습니다. `email`, `name`, `groups` 클레임으로 앱에 제공되므로 앱은 이를 바탕으로 계정을 자동으로 만들고 그룹에 따라 관리자 권한을 줄 수 있습니다;
- 클라이언트마다 로그인을 허용할 사용자나 그룹을 제한할 수 있습니다. PKCE, 새로 고침 토큰, `prompt=none` / `prompt=login`을 지원하며, 공개 클라이언트(단일 페이지 앱, 모바일 앱)는 PKCE를 반드시 사용해야 합니다;
- 로그인에는 웹 인증의 로그인 페이지와 TOTP 2단계 인증을 그대로 사용합니다. 발급자가 통합 로그인 도메인 안에 있으면 어느 사이트에든 로그인한 상태에서는 앱에 다시 로그인할 필요가 없습니다;
- 비밀번호나 TOTP를 바꾸거나, 사용자를 삭제하거나, 허용 목록에서 빼면 이미 발급된 토큰은 즉시 무효가 됩니다. `sub`는 공유 사용자의 고정 ID를 사용하므로 이름을 바꿔도 그대로입니다;
- 문서에 Gitea, OpenList, Grafana 설정 예시를 실었으며, 모두 실제 앱에서 확인했습니다.

## SMB 서비스

「파일 서비스」에 「SMB 서비스」가 추가되어, 로컬 디렉터리를 Windows 탐색기, macOS Finder, Linux와 휴대폰, TV의 SMB 클라이언트에 공유합니다:

- SMB 2.0.2 ~ 3.1.1, NTLMv2 인증과 서명을 지원하며 SMB 3 암호화를 강제할 수 있습니다;
- 사용자 설정은 FTP, WebDAV와 같습니다. 각 사용자는 자신의 공유만 볼 수 있고, 디렉터리마다 읽기 전용으로 설정할 수 있습니다;
- 페이지에 각 공유의 연결 주소를 보여 주며, Bonjour 알림을 켜면 Finder에서 바로 찾을 수 있습니다;
- Linux와 macOS에서만 사용할 수 있습니다. Windows는 445 포트로만 연결하므로, NAS에 내장된 Samba가 이미 사용 중이면 다른 포트를 써야 합니다.

## 로그 필터

「시스템 로그」와 모든 모듈의 로그 카드에서 수준, 출처, 키워드(구문과 제외어 지원), 클라이언트 IP 또는 대역, 시간 범위로 필터링할 수 있으며, Web 서비스는 사이트, 도메인, 상태 코드로도 필터링할 수 있습니다. 필터링은 서버에서 이루어지고, 「이전 로그 불러오기」는 디스크에 기록된 로그 파일까지 계속 찾습니다. Web 서비스 접근 로그와 WAF 적중 로그에는 클라이언트 IP, 도메인, 상태 코드, 규칙 ID가 기록되며, 로그의 태그를 클릭하면 그 값으로 필터링합니다. 로그 API도 같은 필터 매개변수를 지원합니다.

## Web 서비스와 WAF

- 사이트의 요청 헤더와 응답 헤더를 한 줄씩 편집하도록 바꾸었고, 이름과 값을 자주 쓰는 항목(HSTS, CSP, X-Frame-Options 등)에서 고를 수 있습니다. 자주 쓰는 보안 헤더를 한 번에 추가할 수 있고, 형식과 흔한 실수를 실시간으로 검사합니다. 고정 텍스트 사이트의 Content-Type도 자주 쓰는 유형에서 고를 수 있습니다;
- 이름이나 값에 잘못된 문자가 들어간 요청 헤더는 저장할 때 거부됩니다. 이전에는 이런 설정 때문에 사이트 전체가 502를 반환했습니다;
- 리버스 프록시의 「옵션」 옆에 설명을 추가해 여섯 가지 옵션의 역할과 쓰임새를 하나씩 설명합니다;
- WAF 규칙 그룹을 위아래로 옮길 수 있습니다. 허용 규칙(`allow`, `ctl:` 등)은 OWASP CRS보다 위에, `SecRuleRemoveById` 같은 제거 지시문은 CRS보다 아래에 두어야 하며, 화면과 문서 모두에서 설명합니다.

## 수정

- FTP, WebDAV 사용자의 이름을 바꾸고 비밀번호를 다시 입력하지 않으면 저장에 실패했습니다.

## 업그레이드 안내

- 업그레이드 방법: Linux 바이너리는 「정보」 페이지에서 바로 업그레이드하고, Docker는 새 이미지를 받아 컨테이너를 다시 만들고, fnOS는 앱 센터에서 새 `.fpk`를, OpenWrt는 새 `.ipk` / `.apk`를 설치합니다.
- 설정 형식은 하위 호환되므로 바로 업그레이드할 수 있습니다. 공유 사용자는 처음 시작할 때 고정 ID가 자동으로 생성되어 설정 파일에 기록됩니다.
- 웹 인증 로그인 양식은 다른 웹사이트에서 보낸 제출을 거부하며, 일반 로그인에는 영향이 없습니다.
