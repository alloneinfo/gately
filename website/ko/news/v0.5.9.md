# Gately v0.5.9 출시

2026년 10월 26일

이번 버전에서는 File Browser 호스팅([#23](https://github.com/wangwanjie/gately/issues/23))과 IP 주소 인증서([#24](https://github.com/wangwanjie/gately/issues/24))를 추가하고, 호스팅하는 외부 프로그램을 모두 온라인으로 설치하고 롤백할 수 있게 했습니다.

[v0.5.9 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9)

## File Browser

「파일 서비스」에 「File Browser」가 추가되어 웹 파일 관리자 [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser)을 호스팅합니다. 원래의 filebrowser/filebrowser는 2026년에 보관 처리되어 더 이상 보안 문제를 수정하지 않으므로, 계속 유지 관리되는 Quantum 포크를 사용합니다.

- 인스턴스마다 수신 대기 주소와 포트, 접근 경로(경로 기준 리버스 프록시용), 하나 이상의 공유 디렉터리(각각 읽기 전용으로 설정 가능), 인터페이스 언어, 로그인 유지 시간을 설정할 수 있습니다;
- 로그인 방식은 아이디와 비밀번호, 리버스 프록시가 전달하는 사용자 이름 요청 헤더 신뢰(Web 서비스의 웹 인증과 함께 사용), 로그인 없음(눈에 띄는 경고 표시) 중에서 고를 수 있습니다;
- 관리자 비밀번호는 환경 변수로 File Browser에 전달되어 시작할 때마다 동기화되며, 어떤 파일에도 기록되지 않습니다;
- 공유 디렉터리가 없으면 시작을 거부하고, 인스턴스를 삭제하면 그 데이터 디렉터리(사용자, 공유 링크, 캐시)도 함께 삭제하며, 공유 디렉터리 안의 파일은 영향을 받지 않습니다.

자세한 내용은 [파일 서비스](/ko/docs/modules/tools)를 참고하세요.

## IP 주소 인증서와 단기 인증서

ACME 인증서에 「인증서 프로필」이 추가되어 CA 기본값, Let's Encrypt 단기 인증서(약 6일) 또는 CA가 지원하는 다른 프로필 이름을 고를 수 있습니다.

- 도메인 목록에 공인 IPv4, IPv6 주소를 바로 입력해 IP 주소 인증서를 발급할 수 있습니다. IP 인증서는 HTTP-01 검증이 필요하고 Let's Encrypt에서는 단기 인증서를 골라야 하며, 편집기가 이를 안내하고 클릭 한 번으로 설정해 줍니다;
- 기본 제공 CA는 공인 주소에만 발급하므로 사설, 루프백, 100.64.0.0/10 주소는 거부됩니다. 자체 CA(예: step-ca)는 이런 제한이 없지만 HTTP-01 검증은 여전히 필요합니다;
- SNI가 없는 TLS 연결(IP로 접근)에는 로컬 주소와 일치하는 IP 인증서가 자동으로 사용됩니다;
- 단기 인증서는 「단기 인증서 사전 갱신 시간」에 따라 만료 전에 갱신되며(기본 24시간, 최대 80시간), 실패하면 1시간마다 다시 시도합니다. 인증서 카드에는 「단기」 태그와 남은 시간이 표시됩니다.

자세한 내용은 [SSL 인증서](/ko/docs/modules/ssl)를 참고하세요.

## 호스팅 프로그램 온라인 설치

frp, cloudflared, Tailscale, File Browser 페이지에 모두 「온라인 설치」 카드가 생겼습니다:

- 최신 정식 버전이나 지정한 버전(다운그레이드 가능)을 설치합니다. 다운로드 후 SHA-256을 검증하고 이 기기에서 실행되는지 확인한 뒤에 교체하며, 해당 프로그램을 쓰는 프로세스를 자동으로 다시 시작합니다;
- 프로그램마다 다운로드 프록시(http, https, socks5)를 따로 설정할 수 있고, 비워 두면 전역 「업데이트 프록시」를 사용합니다;
- 교체된 이전 버전은 설정 디렉터리의 `bin/.versions/`에 최대 3개까지 보관되며, 클릭 한 번으로 롤백하거나 삭제할 수 있습니다;
- 「제거」는 설치한 프로그램과 모든 이전 버전을 삭제하고 모듈 설정은 유지합니다;
- 페이지 상단의 「기본 설정 복원」은 프로세스를 멈추고 모듈 설정을 기본값으로 되돌리며, 이전 설정은 설정 기록에 보관됩니다;
- Tailscale 온라인 설치는 Linux에서만 제공됩니다(macOS, Windows용 공식 정적 패키지가 없기 때문입니다).

프로그램을 찾는 순서는 페이지에 입력한 경로 → 설정 디렉터리의 `bin/` → `PATH`로 바뀌어, 온라인으로 설치한 프로그램이 우선 적용됩니다. 자세한 내용은 [연결 및 터널링](/ko/docs/modules/tunnels)을 참고하세요.

## 파일 서비스 공유 사용자

WebDAV, FTP, SMB의 공유 사용자는 「파일 서비스 → 파일 공유 사용자」 별도 페이지에서 편집합니다. 이 페이지에는 각 서비스의 활성화 여부와 공유 사용자 허용 여부, 같은 이름의 로컬 사용자에게 가려진 공유 사용자가 표시됩니다. 각 서비스 페이지에는 「공유 사용자 로그인 허용」 스위치만 남습니다. 새 API `GET/PUT /api/fileusers`와 토큰 권한 `fileusers:read`, `fileusers:write`가 추가되었고, 기존 `/api/<서비스>/shared-users`도 계속 사용할 수 있습니다.

## 업그레이드 안내

- 업그레이드 방법: Linux 바이너리는 「정보」 페이지에서 바로 업그레이드하고, Docker는 새 이미지를 받아 컨테이너를 다시 만들고, fnOS는 앱 센터에서 새 `.fpk`를, OpenWrt는 새 `.ipk` / `.apk`를 설치합니다.
- 설정 형식은 하위 호환되므로 바로 업그레이드할 수 있으며, 기존 인증서는 업그레이드 때문에 다시 발급되지 않습니다.
- 찾는 순서가 바뀌어, 설정 디렉터리의 `bin/`에 같은 이름의 프로그램이 있으면 `PATH`의 프로그램보다 먼저 사용됩니다.
- 「기능 모듈」에서 끈 파일 서비스가 있어도 공유 사용자를 변경할 수 있습니다.
