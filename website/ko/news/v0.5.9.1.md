# Gately v0.5.9.1 출시

2026년 10월 26일

v0.5.9 계열의 업데이트로, [issue #25](https://github.com/wangwanjie/gately/issues/25)의 제안을 바탕으로 했으며 편집 후 저장되지 않던 두 곳을 고쳤습니다.

[v0.5.9.1 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9.1)

## HTTP와 HTTPS를 같은 포트에서

HTTPS를 켠 리스너에 「같은 포트의 HTTP」 옵션이 추가되었으며 기본값은 「거부」입니다. 「HTTPS로 리디렉션」을 고르면 `http://호스트:포트`를 `https://호스트:포트`로 리디렉션하고(GET, HEAD는 301, 다른 메서드는 메서드와 본문을 유지하는 308), 「그대로 제공」을 고르면 평문 HTTP로 사이트를 제공합니다. 가정용 회선의 비표준 포트처럼 포트를 하나만 매핑할 수 있고, 방문자가 프로토콜을 잘못 입력해도 열리게 하고 싶을 때 유용합니다.

Gately는 각 연결의 첫 바이트로 TLS와 HTTP를 구분합니다. PROXY 프로토콜 헤더는 그보다 먼저 읽고, HTTP/2 협상과 ACME HTTP-01 검증은 그대로 동작하며, `Alt-Svc`는 HTTPS 응답에서만 보냅니다. nginx 설정을 가져올 때 HTTPS server의 `error_page 497 https://$host:$server_port$request_uri`는 「HTTPS로 리디렉션」으로 변환됩니다. 자세한 내용은 [Web 서비스](/ko/docs/modules/web)를 참고하세요.

## File Browser 접속 주소

File Browser 인스턴스에 Web 서비스로 리버스 프록시한 `https://files.example.com/` 같은 접속 주소를 여러 개 지정할 수 있습니다. 인스턴스 카드에 이 주소들이 표시되고, 비워 두면 이전처럼 수신 주소와 포트로 추정합니다. 첫 번째 주소의 프로토콜, 호스트, 포트는 File Browser의 외부 주소가 되어 공유 링크에 쓰입니다. 자세한 내용은 [파일 서비스](/ko/docs/modules/tools#filebrowser)를 참고하세요.

## 수정

- 기존 File Browser 인스턴스를 편집해 저장하면 `json: unknown field "state"` 오류가 나던 문제를 고쳤습니다.
- 기존 Cloudflare 터널을 편집해 저장할 때 같은 `json: unknown field "state"` 오류가 나던 문제를 고쳤습니다.
- 공유 사용자를 켜면 FTP와 WebDAV 수신 로그에 사용자 수가 0으로 표시되던 문제를 고쳤습니다([issue #26](https://github.com/wangwanjie/gately/issues/26)). 이제 SMB처럼 「사용자 N명, 그중 공유 사용자 M명」으로 표시하며, WebDAV는 공유 사용자가 바뀌면 새 수를 기록합니다.

## 업그레이드 안내

- 「같은 포트의 HTTP」는 기본적으로 꺼져 있어 기존 리스너의 동작은 그대로입니다. 이 옵션을 바꾸면 해당 리스너가 다시 시작되고 기존 연결은 끊깁니다.
- 「그대로 제공」에서는 평문 HTTP로 접속한 사이트가 암호화되지 않으며, 웹 인증과 공유 사용자 비밀번호도 평문으로 전송됩니다. 인터넷에서 접속할 때는 「HTTPS로 리디렉션」을 권장합니다.
