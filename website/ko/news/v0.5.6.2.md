# Gately v0.5.6.2 출시

2026년 10월 23일

v0.5.6 계열의 수정 버전입니다. 모든 배포 방식에서 업그레이드를 권장합니다.

[v0.5.6.2 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.2)

## Docker 29에서 Docker 모듈 사용 가능

Docker 25부터 지원하는 최소 API 버전이 점차 올라가 Docker 29는 1.44 이상이 필요합니다. Gately는 1.41을 고정으로 사용해 Docker 화면에 연결할 수 없다는 메시지가 표시됐습니다. 이제 처음 연결할 때 지원 범위를 읽어 1.41을 지원하면 그대로 쓰고, 지원하지 않으면 데몬의 최소 버전을, 20.10 이전 엔진에서는 엔진 자체 버전을 사용합니다.

## 로그인하지 않았으면 바로 로그인 화면으로

세션은 페이지가 읽을 수 없는 쿠키에 저장되어 있어, 로그인하지 않고 관리 화면을 열면 API가 401을 돌려줄 때까지 개요 화면이 보였습니다. 이제 페이지를 표시하기 전에 세션을 확인해 로그인하지 않았으면 바로 로그인 화면을 보여 주고, 로그인 후 원래 열려던 페이지로 돌아갑니다.

## Lucky에서 가져온 Cloudflare 설정 지원

Lucky의 Cloudflare는 API 토큰만 사용하며, 가져온 설정의 ID 필드에는 다른 서비스의 AccessKey가 남아 있는 경우가 많습니다. Gately는 이를 계정 이메일로 보고 Global API Key 인증을 써서 DDNS와 인증서 검증이 6003 Invalid request headers로 실패했습니다. 이제 ID가 이메일일 때만 Global API Key를 쓰고 그 밖에는 API 토큰으로 인증합니다.

## 이름을 바꾼 DDNS 레코드 즉시 동기화

작업을 수정할 때 도메인, 유형, 회선, TTL을 바꾼 레코드가 이전 동기화 상태를 그대로 이어받아 이미 동기화된 것으로 처리되어 새 레코드가 만들어지지 않았습니다. 이제 저장 후 다시 동기화합니다.

## Web 서비스 로그인 화면과 오류 페이지 새 디자인

웹 인증을 켠 사이트의 로그인 화면, 404·502 오류 페이지, 관리 콘솔에서 보안 입구를 잘못 입력했을 때의 안내 페이지를 시스템의 라이트/다크 테마를 따르는 통일된 카드 디자인으로 바꿨습니다. 2단계 인증은 팝업으로 바뀌어, 사용자 이름과 비밀번호가 확인되면 같은 화면에서 인증 코드 창이 열리고 6자리를 입력하면 자동으로 제출됩니다. 예전에는 인증 코드가 필요할 때 입력한 사용자 이름과 비밀번호가 지워졌지만 이제 다시 입력할 필요가 없고, 비밀번호를 틀려도 사용자 이름은 유지됩니다. CLI·API 등 브라우저가 아닌 요청에는 기존처럼 일반 텍스트를 반환합니다.

## 업그레이드 안내

- Docker는 새 이미지를 받아 컨테이너를 다시 만들면 됩니다. 다른 배포 방식은 「설정」에서 온라인 업그레이드하거나 새 패키지를 덮어써 설치하세요.
- 6003 오류 때문에 Cloudflare ID를 직접 비운 작업은 되돌리지 않아도 됩니다.
