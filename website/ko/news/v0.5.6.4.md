# Gately v0.5.6.4 출시

2026년 10월 23일

v0.5.6 계열의 기능 업데이트로, [issue #13](https://github.com/wangwanjie/gately/issues/13)의 제안을 바탕으로 인증서를 다른 서비스에 배포하는 방식을 개선했습니다.

[v0.5.6.4 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.4)

## 여러 로컬 디렉터리에 복사

인증서의 "자동 배포"에 "로컬 디렉터리에 복사"가 추가되었습니다. 디렉터리를 원하는 만큼 추가할 수 있고, 디렉터리마다 "복사 후 실행" 명령을 따로 둘 수 있습니다. 예를 들어 nginx용 디렉터리는 `nginx -s reload`, ocserv용 디렉터리는 `systemctl reload ocserv`를 실행합니다. 인증서가 발급·갱신·업데이트되면 자동으로 복사하고 명령을 실행하며, 실패하면 1시간마다 재시도하고 "인증서: 배포 실패" 알림을 보냅니다. 디렉터리의 인증서 파일이 삭제되거나 바뀌면 다음 검사 때 다시 복사합니다.

## 인증서 파일 이름 지정

"로컬 디렉터리에 복사"와 "SSH 호스트에 업로드" 모두 인증서(전체 체인)와 개인 키의 파일 이름을 `fullchain.pem`, `privkey.pem`처럼 지정할 수 있습니다. 둘 다 입력하면 이 두 파일만 쓰므로 명령에서 이름을 바꿀 필요가 없습니다. 비워 두면 기존처럼 `<메모>.crt`, `.pem`, `.key`를 씁니다. 명령의 `$certFile`, `$keyFile`은 실제로 쓴 파일을 가리킵니다.

## 업그레이드 안내

- 기존 "인증서 매핑"은 그대로이며 계속 사용할 수 있습니다. 디렉터리가 여러 개 필요하면 "자동 배포"에 추가하세요.
- 기존 SSH와 Docker 배포 대상은 업그레이드 후 다시 배포되지 않습니다.
- Gately가 Docker에서 실행 중이면 로컬 디렉터리와 명령은 컨테이너 안의 것이므로 대상 디렉터리를 컨테이너에 마운트하세요.
