# Gately v0.5.5 출시

2026년 10월 21일

이번 릴리스의 주제는 "nginx에서 옮겨 오고, 옮긴 뒤에는 신경 쓸 일을 줄이기"입니다. 기존 nginx 사이트를 그대로 가져올 수 있고, 갱신된 인증서는 다른 호스트와 컨테이너로 자동 전달되며, 클라우드 드라이브와 WebDAV 사이트에도 WAF를 걸 수 있습니다. IP 접근 제어는 정기적으로 갱신되는 지역별 IP 목록을 참조할 수 있고, 네트워크 자가 점검은 인증서가 없는 사이트와 frp 충돌을 미리 찾아냅니다.

[v0.5.5 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.5)

## nginx 설정 가져오기

Web 서비스 페이지에 「nginx 가져오기」가 추가되었습니다. nginx가 설치된 호스트에서 `nginx -T`를 실행하고 전체 출력을 붙여 넣으면 됩니다. include된 파일은 nginx와 같은 방식으로 펼쳐집니다.

- 가져오기 전에 미리 보기를 표시합니다. 수신 포트별로 각 사이트의 유형, 백엔드나 디렉터리, 원본 파일과 줄 번호, 그리고 변수 사용, 정규식 location, 인증서 누락처럼 확인이 필요한 부분을 보여 줍니다.
- 리버스 프록시(upstream의 가중치, 백업 서버, 로드 밸런싱 정책 포함), 정적 디렉터리, 리디렉션, 고정 응답, 응답 헤더와 요청 헤더, 압축, `allow` / `deny`, 그리고 location 수준의 경로별 백엔드, 접근 제어, 리디렉션을 변환합니다.
- `auth_request`는 포워드 인증으로 변환되며, Authelia의 일반적인 구성(`set` 변수, `error_page 401` 로그인 리디렉션)도 그대로 변환됩니다. 일부 location에서만 사용하면 "지정한 경로만 인증"으로 변환합니다. `auth_basic`은 공유 사용자를 쓰는 기본 인증으로 변환되므로 가져온 뒤 보호되지 않은 사이트가 생기지 않습니다.
- 같은 포트의 사이트는 기존 리스너에 합쳐지고, 이미 있는 도메인은 건너뛰므로 여러 번 가져와도 됩니다. 기본적으로 비활성화 상태로 가져오므로 nginx와 나란히 운영하면서 하나씩 확인하기 좋습니다.

이 기능은 실제 운영 설정(사이트 77개, Authelia, upstream)으로 검증했으며, 변환 결과가 수동 이전과 같았습니다. [웹 서비스 · nginx 설정 가져오기](/ko/docs/modules/web#import-nginx)를 참고하세요.

## 인증서 자동 배포

인증서 편집 창에 「자동 배포」가 추가되어, 인증서가 발급·갱신·업데이트되면 자동으로 실행됩니다.

- **SSH 호스트에 업로드**: Web 터미널에 있는 SSH 연결을 선택하면 인증서를 원격 디렉터리에 기록한 뒤 `systemctl reload nginx` 같은 명령을 실행합니다. 명령에서는 `$certName`, `$certDir`, `$certFile`, `$keyFile`을 쓸 수 있습니다. 파일은 먼저 임시 파일에 쓴 뒤 교체하며, 개인 키 권한은 0600입니다.
- **로컬 컨테이너 재시작**: 인증서가 바뀌면 선택한 Docker 컨테이너를 차례로 재시작합니다.

자동 배포는 알 수 없는 호스트를 신뢰하지 않으므로 SSH 연결로 Web 터미널에서 먼저 한 번 접속해야 합니다. 실패하면 1시간마다 다시 시도하고 새 알림 「인증서: 배포 실패」를 보냅니다. 인증서 카드의 「지금 배포」를 누르면 즉시 실행하고 대상별 결과를 표시합니다. [SSL 인증서](/ko/docs/modules/ssl)를 참고하세요.

## WAF: 대용량 업로드와 WebDAV

- **요청 본문 검사 한도**를 조정할 수 있습니다(기본 12.5 MB, 최대 1024 MB). 한도를 넘으면 거부하거나, 앞부분만 검사하고 나머지는 그대로 전달할 수 있습니다.
- **본문 검사 제외 경로**: 업로드 엔드포인트는 요청 본문을 검사하지 않고, 요청 헤더, URL, 파라미터는 평소처럼 검사합니다.
- **WebDAV·업로드 호환**: PUT, PROPFIND, MKCOL, MOVE, COPY, LOCK 등의 메서드와 `Lock-Token`, `If`, `Content-Range` 요청 헤더를 허용하고 업로드 콘텐츠 유형을 더 이상 제한하지 않습니다. 클라우드 드라이브, WebDAV, 파일 관리 사이트에 WAF를 걸어도 정상적으로 쓸 수 있으며, 인젝션, 경로 탐색 등의 공격은 그대로 차단합니다.
- 모든 인스턴스가 curl, rclone이 큰 파일을 업로드할 때 보내는 `Expect: 100-continue`를 허용합니다. 이전에는 OWASP CRS 4가 이런 업로드를 차단했습니다.

[WAF 방화벽](/ko/docs/modules/waf)을 참고하세요.

## 구독 IP 목록

「Web 서비스 → 전역 설정」에서 주소로 IP 목록을 구독하고 정기적으로 갱신할 수 있습니다. 예를 들어 [metowolf/iplist](https://github.com/metowolf/iplist)의 중국 성·시별 IP 대역을 쓸 수 있습니다. 사이트와 경로 규칙의 허용 목록, 차단 목록은 여러 목록을 참조해 직접 입력한 IP 대역과 함께 판단합니다. 내려받은 내용은 로컬에 캐시되므로 재시작 후에도 네트워크 없이 동작하며, 내용을 인식할 수 없으면 이전 목록을 유지합니다. [웹 서비스 · 구독 IP 목록](/ko/docs/modules/web)을 참고하세요.

## 네트워크 자가 점검 항목 2개 추가

- **HTTPS 사이트 인증서**: 일치하는 인증서가 없는 도메인을 나열합니다. 이런 도메인은 TLS 핸드셰이크에서 실패합니다.
- **frp 충돌**: frpc에서 이름이 겹치는 프록시와 frps가 보고한 프록시 이름, 도메인, 원격 포트 충돌을 나열합니다. 여러 기기가 같은 frpc 설정을 복사해 쓰면 나중에 연결된 기기의 등록이 실패하고 해당 사이트가 시간 초과됩니다.

## 기타 개선

- 온라인 업그레이드가 `v0.5.4.1` 같은 네 자리 버전 번호를 지원합니다. 개발 빌드처럼 버전을 비교할 수 없으면 "최신 버전"으로 표시하는 대신 그 사실을 명확히 알려 줍니다.
- 인증서 배포, nginx 가져오기 미리 보기 등의 API가 반환하는 설명 문구가 UI 언어로 표시됩니다.

## 업그레이드

- v0.5.4부터 Linux 바이너리 설치는 정보 페이지에서 v0.5.5로 바로 업그레이드할 수 있습니다. Docker는 새 이미지를 받아 컨테이너를 다시 만들고, fnOS는 앱 센터에서 새 `.fpk`를, OpenWrt는 새 `.ipk` / `.apk`를 설치하세요.
- 이미 WAF를 건 클라우드 드라이브나 WebDAV 사이트는 업그레이드 후 해당 WAF 인스턴스에서 「WebDAV·업로드 호환」을 켜면 정상적으로 업로드할 수 있습니다.
