# Gately v0.6.0 출시

2026년 10월 27일

이번 버전에서는 frp를 여러 인스턴스로 실행할 수 있고, Web 서비스에 사용자별 라우팅([#29](https://github.com/wangwanjie/gately/issues/29)), 사이트 그룹과 정렬([#28](https://github.com/wangwanjie/gately/issues/28)), 로그인 쿠키 전달([#30](https://github.com/wangwanjie/gately/issues/30))이 추가되었습니다. 다른 DNS 제공자에 호스팅된 하위 도메인의 인증서 발급 실패도 고쳤습니다([#27](https://github.com/wangwanjie/gately/issues/27)).

[v0.6.0 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0)

## frp 다중 인스턴스

- 여러 frpc 인스턴스(각각 frps 한 대에 연결)와 여러 frps 인스턴스(각각 자기 포트에서 수신)를 동시에 실행할 수 있습니다. 각 인스턴스는 독립된 프로세스로 자체 설정 파일과 로그 소스를 가지며, 따로 켜고 끄기, 재시작, 편집, 삭제할 수 있습니다.
- 프록시는 하나의 frpc 인스턴스에 속하고 목록을 인스턴스별로 필터링할 수 있습니다. 프록시를 바꾸면 설정이 바뀐 인스턴스만 재시작되고, frpc 인스턴스를 삭제하면 그 프록시도 함께 삭제됩니다.
- 프로그램 경로는 별도의 「프로그램」 카드로 옮겨졌습니다.
- ini / toml 설정을 가져올 때 기존 인스턴스나 새 인스턴스를 선택할 수 있고, Lucky 가져오기는 모든 frpc / frps 인스턴스를 가져옵니다.
- 이전 버전의 단일 frpc / frps 설정은 업그레이드할 때 frpc / frps라는 이름의 인스턴스로 자동 이전되며, 토큰과 프록시는 그대로 유지됩니다.

자세한 내용은 [네트워킹 및 터널](/ko/docs/modules/tunnels)을 참고하세요.

## Web 서비스

- **로그인 사용자별 라우팅**: 기본 인증, 웹 인증, 전달 인증을 켠 리버스 프록시 사이트는 지정한 사용자를 각자의 백엔드로 보낼 수 있습니다. nginx의 `map $remote_user $backend`와 비슷합니다. 사용자는 사이트 사용자, 공유 사용자, 서드파티 로그인의 `제공자:ID`, 전달 인증이 돌려준 `Remote-User`로 지정할 수 있습니다. 목록에 없는 사용자와 공개 경로에서 로그인하지 않은 방문자는 사이트 백엔드를 사용합니다. `X-Remote-User` 같은 헤더로 사용자 이름을 백엔드에 넘길 수도 있으며, 방문자가 직접 보낸 같은 이름의 헤더(하이픈 대신 밑줄을 쓴 표기 포함)는 항상 제거됩니다.
- **사이트 그룹, 정렬, 검색**: 사이트에 그룹을 지정할 수 있고, 목록은 리스너별로 접을 수 있는 그룹으로 표시됩니다. 「정렬」 모드에서는 사이트를 위아래로 옮기거나 드래그할 수 있고, 그룹 전체를 옮기거나 리스너 순서를 바꿀 수 있습니다. 상단 검색창은 도메인, 이름, 그룹, 백엔드, 메모로 필터링합니다. 순서는 목록 표시에만 영향을 주며 도메인 매칭과는 무관합니다.
- **Gately 로그인 쿠키 전달**: 리버스 프록시 사이트의 새 옵션입니다. 켜면 싱글 사인온과 사이트 세션 쿠키가 그대로 백엔드로 전달되므로, 공개된 Gately는 WAF와 접근 제어만 맡고 내부망 Gately가 웹 인증과 싱글 사인온을 처리할 수 있습니다. 같은 사이트의 인증과 함께 켤 수 없습니다.

자세한 내용은 [웹 서비스](/ko/docs/modules/web)를 참고하세요.

## 인증서

영역을 비워 두면 DNS-01 검증은 먼저 SOA 조회로 검증 레코드의 권한 있는 영역을 찾습니다. 다른 DNS 제공자에 따로 호스팅된 하위 도메인(예: example.com과 따로 호스팅된 web.example.com)과 다단계 접미사도 올바르게 인식합니다. 조회에 실패하거나 찾은 영역이 등록 가능한 도메인보다 짧으면(예: 로컬 DNS가 상위 도메인을 덮어쓴 경우) 도메인 이름으로 영역을 추정하고 그 이유를 로그에 남깁니다. 인증서마다 설정한 DNS 서버는 이제 해당 인증서에만 사용됩니다.

## 저장된 비밀번호 표시

마스킹된 비밀번호, 토큰, 키 옆에 눈 모양 버튼이 생겼으며, 누르면 새 `.../secrets` 엔드포인트에서 평문을 가져옵니다:

- 쓰기 권한이 필요합니다. 읽기 전용 계정과 읽기 전용 API 토큰은 403을 받고, 조회할 때마다 감사 로그에 기록됩니다.
- 웹 터미널의 연결 및 인증 프리셋 비밀번호는 터미널을 열 때와 마찬가지로 터미널의 2단계 확인을 먼저 통과해야 합니다.
- bcrypt로 저장된 웹 사용자 비밀번호, OIDC 클라이언트 시크릿, 개인 키는 반환되지 않습니다.
- 2단계 로그인을 켠 공유 사용자는 QR 코드를 다시 볼 수 있습니다.
- `gately mcp`의 기본 읽기 전용 모드에서는 이 엔드포인트를 제공하지 않으며, `--write`를 붙이면 제공합니다.

## 업그레이드 안내

- 업그레이드 방법: Linux 바이너리는 「정보」 페이지에서 바로 업그레이드하고, Docker는 새 이미지를 받아 컨테이너를 다시 만들고, fnOS는 앱 센터에서 새 `.fpk`를, OpenWrt는 새 `.ipk` / `.apk`를 설치합니다.
- 설정 형식은 하위 호환되므로 바로 업그레이드할 수 있습니다. 이전 frp 설정은 처음 시작할 때 인스턴스로 이전되며, 이전 버전이 만든 `frp/frpc.toml`과 `frp/frps.toml`은 삭제됩니다.
- `/api/frp/client`와 `/api/frp/server` 엔드포인트는 제거되고 `/api/frp/clients`, `/api/frp/servers`, `/api/frp/settings`로 바뀌었습니다. 이전 엔드포인트를 호출하는 스크립트는 수정해야 합니다.
- Docker 레지스트리 비밀번호의 마스크는 다른 모듈과 같은 별표 8개로 바뀌었고, 이전의 별표 6개도 계속 인식됩니다.
