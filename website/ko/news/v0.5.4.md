# Gately v0.5.4 출시

2026년 10월 21일

이번 릴리스는 설치와 업그레이드에 관한 것입니다. Linux 바이너리 설치(systemd, PVE LXC 컨테이너, 수동으로 설치한 OpenWrt 등)는 이제 관리 UI에서 바로 업그레이드할 수 있고, OpenWrt와 iStoreOS 사용자는 시스템 패키지 관리자로 Gately를 설치할 수 있습니다.

[v0.5.4 다운로드](/ko/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.4)

## 온라인 업그레이드

정보 페이지에서 "업데이트 확인"을 누르면 대화 상자에 새 버전, 출시일, 릴리스 노트가 표시됩니다. "지금 업그레이드"를 누르면 Gately는 다음 순서로 진행합니다.

1. GitHub에서 이 플랫폼용 릴리스 패키지를 내려받습니다.
2. 같은 릴리스의 `checksums.txt`로 SHA-256을 확인합니다.
3. 새 바이너리를 시험 실행해 이 기기에서 동작하는지 확인합니다.
4. 실행 파일을 교체하고 그 자리에서 재시작합니다. 이전 버전은 같은 디렉터리에 `gately.old`로 남겨 두어 롤백할 수 있습니다.

대화 상자에는 현재 단계, 다운로드 진행률과 속도가 표시되며, 바이너리를 교체하기 전에는 언제든 취소할 수 있습니다. 페이지를 새로 고쳐도 아직 진행 중인 업그레이드를 이어서 보여 주고, 실패하면 원인과 함께 다시 시도 버튼을 표시합니다.

- **PVE LXC 컨테이너**: OCI 이미지로 만든 LXC 컨테이너도 온라인으로 업그레이드할 수 있어 삭제 후 다시 만들 필요가 없습니다.
- **업데이트 프록시**: 사용하는 네트워크에서 GitHub 접속이 불안정하면 정보 페이지나 「설정 → 네트워크 및 실행」에서 http, https, socks5 프록시를 설정하세요. 업데이트 확인과 다운로드 모두 이 프록시를 사용합니다.
- **오프라인 업그레이드와 롤백**: "업그레이드 패키지 업로드"는 릴리스 tar.gz나 압축을 푼 바이너리를 버전 제한 없이 받으므로 롤백에도 쓸 수 있습니다.
- **관리자가 실행할 때만 동작**: Gately는 스스로 버전을 내려받거나 설치하지 않습니다. Docker, fnOS, OpenWrt 패키지 설치는 각자의 업그레이드 방법을 안내합니다.

[설치 및 배포 · 온라인 업그레이드](/ko/docs/guide/install#online-upgrade)를 참고하세요.

## OpenWrt 패키지

이제 모든 릴리스에 amd64 / arm64 / arm / mipsle / mips / riscv64용 OpenWrt 패키지가 포함됩니다.

- OpenWrt 24.10 이하(iStoreOS 포함): `opkg install ./gately_v0.5.4_openwrt_<arch>.ipk`
- OpenWrt 25.12 이상: `apk add --allow-untrusted ./gately_v0.5.4_openwrt_<arch>.apk`

설치하면 부팅 시 자동 시작이 활성화되고 서비스가 바로 시작되며, 관리 UI는 `http://<라우터 주소>:16680`입니다. 설정은 `/etc/gately`에 저장되며 업그레이드, 제거, 펌웨어 업그레이드 후에도 유지됩니다. 업그레이드하려면 새 버전 패키지를 설치하면 됩니다. 설치 전에 장치 아키텍처를 확인하므로 `/etc/openwrt_release`의 `DISTRIB_ARCH`에 맞는 패키지를 고르세요. 바이너리는 약 35 MB이므로 x86 소프트 라우터, ARM64 박스 등 저장 공간이 넉넉한 장치에 적합합니다.

[설치 및 배포 · OpenWrt](/ko/docs/guide/install#openwrt)를 참고하세요.

## 수정 사항

- Gately 자체를 거쳐 접속한 관리 UI가 설정을 저장할 때 끊기지 않습니다. 포트 포워딩 규칙을 편집할 때 수신 포트, 프로토콜, 모드, 제한이 그대로이면 대상과 SNI 라우트를 그 자리에서 바꾸고 기존 연결을 유지합니다. 포트 포워딩이나 웹 서비스 설정을 저장해도 모든 리스너를 재시작하지 않습니다.
- WAF가 `credentials`나 `forwardAuth` 같은 JSON 필드 이름을 OS 파일 접근으로 오탐하지 않습니다. 이 오탐 때문에 DDNS 작업을 저장하거나 웹 서비스 리스너를 추가할 때 403이 반환되었습니다.
- 도메인, IP 목록, 헤더, STUN 서버 같은 목록 입력란이 입력 중에 Enter, 쉼표, 공백을 삼키지 않습니다.
- mips / mipsle 바이너리를 소프트 플로트로 빌드하여 하드웨어 FPU가 없는 라우터에서도 동작합니다.
- 버전 비교가 semver를 따르므로 더 새로운 빌드에 이전 버전으로의 "업그레이드"를 제안하지 않습니다.

## 업그레이드

- 온라인 업그레이드는 v0.5.4부터 제공되므로 이번 한 번은 직접 업그레이드해야 합니다. 바이너리를 교체하고 재시작하거나, 새 Docker 이미지를 받아 컨테이너를 다시 만들거나, fnOS 앱 센터에서 새 `.fpk`를 설치하세요. 그다음부터는 정보 페이지에서 업그레이드할 수 있습니다.
- OpenWrt에 Gately를 수동으로 설치했다면 그 위에 `.ipk` / `.apk`를 설치하면 됩니다. `/etc/gately`의 설정은 그대로 사용됩니다.
