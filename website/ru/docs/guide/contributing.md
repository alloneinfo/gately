# Участие в разработке

Gately — проект с открытым кодом, развиваемый сообществом; Issue и Pull Request приветствуются. Репозиторий: <https://github.com/wangwanjie/gately>

## Локальная разработка

Зависимости: Go 1.26+, Node.js 24+, pnpm.

```bash
make web      # сборка фронтенда (вывод в web/dist, встраивается через go:embed)
make build    # компиляция bin/gately
make test     # go test -race ./...
make lint     # gofmt, go vet, проверка типов фронтенда
```

При разработке фронтенда запустите `cd web && pnpm dev`: запросы `/api` проксируются на локальный `127.0.0.1:16680`.

## Правила

- Совместимость с Lucky строится на публично наблюдаемом поведении, интерфейсах и форматах конфигурации. Не отправляйте код, скопированный из бинарных файлов или фронтенд-сборок Lucky.
- Новому модулю нужны: структура конфигурации и валидация, запуск и остановка во время работы, REST-интерфейс, юнит-тесты; модуль, который можно мигрировать из Lucky, реализует `luckyimport.Importer`, а модуль, статус которого показывается на странице «Обзор», реализует `module.Summarizer`.
- Комментарии в коде пишутся на китайском; в управляющих конструкциях обязательны фигурные скобки.

## Дополнительные тесты

Часть тестов по умолчанию пропускается и требует дополнительных условий:

| Тест | Как включить |
| --- | --- |
| Сквозной тест ACME (Pebble) | Установите pebble и pebble-challtestsrv, задайте `GATELY_PEBBLE_BIN`, `GATELY_PEBBLE_SRC` |
| Реальные публичные STUN-серверы | `GATELY_NET_TEST=1` |
| Проверка импорта на реальной конфигурации Lucky | `GATELY_LUCKY_SAMPLE` и другие, см. `TestImportRealSample` в каждом модуле |
