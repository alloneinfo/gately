# Вышла Gately v0.5.5

21 октября 2026 г.

Этот релиз посвящён переезду с nginx и тому, чтобы после переезда было меньше забот: существующие сайты nginx можно импортировать напрямую, продлённые сертификаты автоматически отправляются на другие хосты и в контейнеры, облачные диски и сайты WebDAV можно поставить за WAF, контроль доступа по IP умеет ссылаться на регулярно обновляемые списки IP по провинциям и городам, а самопроверка сети заранее находит сайты без сертификата и конфликты frp.

[Скачать v0.5.5](/ru/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.5)

## Импорт конфигурации nginx

На странице «Веб-службы» появилась кнопка «Импорт nginx». Выполните `nginx -T` на хосте nginx и вставьте весь вывод — файлы из include раскрываются так же, как это делает nginx.

- Перед импортом показывается предпросмотр: по каждому слушающему порту перечислены сайты с типом, бэкендом или каталогом, исходным файлом и номером строки, а также места, требующие внимания, например переменные, location с регулярными выражениями или отсутствующие сертификаты;
- Преобразуются обратные прокси (включая веса, резервные серверы и стратегии балансировки из upstream), статические каталоги, перенаправления, фиксированный текст, заголовки ответа и запроса, сжатие, `allow` / `deny`, а также бэкенды по путям, контроль доступа и перенаправления на уровне location;
- `auth_request` преобразуется в forward auth; типичные конфигурации Authelia (переменные `set`, переход на страницу входа через `error_page 401`) переносятся напрямую, а если он включён только в части location, получается «аутентификация только для указанных путей». `auth_basic` преобразуется в базовую аутентификацию с общими пользователями, так что после импорта все сайты остаются защищёнными;
- Сайты на том же порту добавляются к существующему прослушиванию, уже имеющиеся домены пропускаются, поэтому импорт можно повторять. По умолчанию сайты импортируются отключёнными, чтобы их можно было по одному сверить, пока nginx продолжает работать.

Функция проверена на реальной рабочей конфигурации (77 сайтов, Authelia, upstream): результат совпадает с ручным переносом. Подробнее: [Веб-службы · Импорт конфигурации nginx](/ru/docs/modules/web#import-nginx).

## Автоматическое развёртывание сертификатов

В окне редактирования сертификата появился раздел «Автоматическое развёртывание», который срабатывает после выпуска, продления или обновления:

- **Загрузить на SSH-хост**: выберите SSH-подключение, уже настроенное в веб-терминале. Сертификат записывается в удалённый каталог, после чего выполняется команда, например `systemctl reload nginx`; в команде доступны `$certName`, `$certDir`, `$certFile` и `$keyFile`. Файлы сначала записываются во временные и затем подменяются, права на закрытый ключ — 0600;
- **Перезапустить локальные контейнеры**: после изменения сертификата выбранные контейнеры Docker перезапускаются по очереди.

Автоматическое развёртывание не доверяет неизвестным хостам: к SSH-подключению нужно сначала один раз подключиться в веб-терминале. При ошибке развёртывание повторяется каждый час и генерируется новое уведомление «Сертификат: ошибка развёртывания»; кнопка «Развернуть сейчас» на карточке сертификата запускает его сразу и показывает результат по каждой цели. Подробнее: [SSL-сертификаты](/ru/docs/modules/ssl).

## WAF: большие загрузки и WebDAV

- **Лимит проверки** тела запроса настраивается (по умолчанию 12,5 МБ, максимум 1024 МБ); при превышении запрос можно отклонить или проверить только начало, а остальное передать без изменений;
- **Пути без проверки тела**: у эндпоинтов загрузки тело запроса не проверяется, а заголовки, URL и параметры проверяются как обычно;
- **Совместимость с WebDAV и загрузками**: разрешает методы PUT, PROPFIND, MKCOL, MOVE, COPY, LOCK и другие, заголовки `Lock-Token`, `If` и `Content-Range` и снимает ограничение на тип содержимого загрузок. Облачные диски, сайты WebDAV и файловые менеджеры нормально работают за WAF, а атаки вроде инъекций и обхода путей по-прежнему блокируются;
- Все экземпляры пропускают `Expect: 100-continue`, который curl и rclone отправляют при загрузке больших файлов; раньше OWASP CRS 4 блокировал такие загрузки.

Подробнее: [Брандмауэр WAF](/ru/docs/modules/waf).

## Подписные списки IP

В разделе «Веб-службы → Глобальные настройки» можно подписаться на списки IP по URL и обновлять их по расписанию, например на диапазоны IP китайских провинций и городов из [metowolf/iplist](https://github.com/metowolf/iplist). Белые и чёрные списки сайтов и правил путей могут ссылаться на несколько списков, которые проверяются вместе с диапазонами IP, введёнными вручную. Загруженное содержимое кэшируется локально, поэтому после перезапуска сеть не нужна; если содержимое не удаётся разобрать, сохраняется предыдущая версия списка. Подробнее: [Веб-службы · Подписные списки IP](/ru/docs/modules/web).

## Две новые проверки в самопроверке сети

- **Сертификаты HTTPS-сайтов**: перечисляет домены без подходящего сертификата — запросы к ним обрываются на этапе TLS-рукопожатия;
- **Конфликты frp**: перечисляет прокси frpc с одинаковыми именами, а также конфликты имён прокси, доменов или удалённых портов, о которых сообщает frps. Когда несколько устройств используют копию одной конфигурации frpc, устройство, подключившееся позже, не может зарегистрироваться, и соответствующие сайты перестают отвечать по тайм-ауту.

## Другие улучшения

- Онлайн-обновление поддерживает номера версий из четырёх частей, например `v0.5.4.1`; если версии нельзя сравнить (например, у сборки для разработки), об этом прямо сообщается, а надпись «У вас последняя версия» больше не показывается.
- Пояснения, которые возвращают API развёртывания сертификатов, предпросмотра импорта nginx и другие, выводятся на языке интерфейса.

## Обновление

- Начиная с v0.5.4 бинарные установки в Linux обновляются до v0.5.5 прямо со страницы «О программе»; для Docker скачайте новый образ и пересоздайте контейнер, в fnOS установите новый `.fpk` через Центр приложений, в OpenWrt — новый `.ipk` / `.apk`.
- Если облачные диски или сайты WebDAV уже стоят за WAF, после обновления включите в соответствующем экземпляре WAF «Совместимость с WebDAV и загрузками», чтобы загрузки работали.
