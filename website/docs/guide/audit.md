# 审计与配置历史

Gately 手握 DNS 密钥与证书私钥，所以谁在何时做了什么、配置如何变化，都应当可以追查和撤销。

## 操作审计

侧边栏「系统 → 操作审计」列出以下操作，按时间倒序，可按类别筛选或按路径、用户、IP 搜索：

| 类别 | 记录内容 |
| --- | --- |
| 登录 | 密码、Passkey 与第三方登录的成功和失败，以及退出登录 |
| 变更 | 管理后台与 API 令牌发起的所有写操作（新增、修改、删除、启停、回滚等） |
| 敏感访问 | 下载配置备份、诊断包、证书私钥，打开 Web 终端或容器终端等 |

每条记录包含时间、操作者（用户名或 `api-token:<令牌名>`）、来源 IP、方法、路径与状态码。**不记录请求体与任何密钥**。

- 日志写入配置目录下的 `audit.log`（JSON Lines），单文件超过 5 MiB 后轮转，保留 3 份历史；
- 管理界面放在本机反向代理之后时，记录的是真实来源，并单独标注经过的代理地址，原理见 [安全模型](/docs/guide/security)；
- 变更与敏感访问会作为 `audit.change`、`audit.access` 事件发出，可在 [通知中心](/docs/modules/notify) 用「配置变更」「安全与登录」模板推送；
- 只读账号与 API 令牌无法查看审计日志。

## 配置历史与回滚

每次覆盖配置文件之前，Gately 会把旧内容保存为一个历史版本，位于配置目录的 `history/<名称>/`，每个配置保留最近 30 个。`account.json`（账号凭据）与 `tokens.json`（令牌）不记录历史。

在「系统 → 配置历史」中：

1. 选择配置文件，查看各历史版本的保存时间与大小；
2. 点击「对比」查看该版本与当前配置的行级差异；
3. 点击「回滚」恢复该版本，Gately 随后自动重启使其生效。

回滚前的当前内容也会保存为新的历史版本，因此回滚本身可以再次撤销。
