# Gately v0.5.9.1 veröffentlicht

26. Oktober 2026

Dies ist ein Update der Reihe v0.5.9 auf Anregung von [issue #25](https://github.com/wangwanjie/gately/issues/25); außerdem werden zwei Editoren repariert, die nicht speichern konnten.

[v0.5.9.1 herunterladen](/de/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9.1)

## HTTP und HTTPS auf demselben Port

Listener mit HTTPS erhalten die Option „HTTP auf demselben Port“, standardmäßig „Ablehnen“. Mit „Auf HTTPS umleiten“ wird `http://host:port` auf `https://host:port` umgeleitet (301 für GET und HEAD, 308 für andere Methoden, damit Methode und Body erhalten bleiben); mit „Ausliefern“ werden die Sites über unverschlüsseltes HTTP beantwortet. Das hilft, wenn nur ein Port weitergeleitet werden kann und Besucher sich beim Schema vertippen können, etwa bei einem nicht standardmäßigen Port am Heimanschluss.

Gately unterscheidet TLS und HTTP am ersten Byte jeder Verbindung. PROXY-Protokoll-Header werden weiterhin zuvor gelesen, HTTP/2-Aushandlung und ACME-HTTP-01-Challenges funktionieren weiter, und `Alt-Svc` wird nur über HTTPS gesendet. Beim Import von nginx-Konfigurationen wird `error_page 497 https://$host:$server_port$request_uri` in einem HTTPS-server zu „Auf HTTPS umleiten“. Siehe [Webdienst](/de/docs/modules/web).

## Zugriffs-URLs für File Browser

Eine File-Browser-Instanz kann mehrere Zugriffs-URLs haben, etwa `https://files.example.com/` hinter dem Reverse Proxy des Webdienstes. Die Instanzkarte zeigt sie an; ist die Liste leer, wird die Adresse weiterhin aus Listen-Adresse und Port abgeleitet. Schema, Host und Port der ersten URL werden zur externen URL von File Browser, die Freigabelinks verwenden. Siehe [Dateidienste](/de/docs/modules/tools#filebrowser).

## Fehlerbehebungen

- Das Speichern einer bearbeiteten File-Browser-Instanz schlug mit `json: unknown field "state"` fehl. Behoben.
- Das Speichern eines bearbeiteten Cloudflare-Tunnels schlug mit demselben Fehler `json: unknown field "state"` fehl. Behoben.
- Bei aktivierten gemeinsamen Benutzern zeigten die Listen-Logs von FTP und WebDAV 0 Benutzer ([issue #26](https://github.com/wangwanjie/gately/issues/26)). Sie lauten jetzt wie bei SMB „N Benutzer, davon M gemeinsame Benutzer“, und WebDAV protokolliert die neuen Zahlen, wenn sich die gemeinsamen Benutzer ändern.

## Hinweise zum Upgrade

- „HTTP auf demselben Port“ ist standardmäßig aus, vorhandene Listener verhalten sich also wie bisher. Eine Änderung startet den Listener neu und trennt offene Verbindungen.
- Mit „Ausliefern“ sind über HTTP aufgerufene Sites unverschlüsselt, auch Passwörter für Web-Authentifizierung und gemeinsame Benutzer werden im Klartext übertragen. Für Zugriffe aus dem Internet empfiehlt sich „Auf HTTPS umleiten“.
