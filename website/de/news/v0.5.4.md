# Gately v0.5.4 veröffentlicht

21. Oktober 2026

In diesem Release geht es um Installation und Upgrade. Linux-Binärinstallationen (systemd, PVE-LXC-Container, manuell eingerichtetes OpenWrt usw.) lassen sich jetzt direkt in der Verwaltungsoberfläche aktualisieren, und Nutzer von OpenWrt und iStoreOS können Gately mit dem Paketmanager des Systems installieren.

[v0.5.4 herunterladen](/de/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.4)

## Online-Upgrade

Klicken Sie auf der Seite „Über“ auf „Nach Updates suchen“. Ein Dialog zeigt die neue Version, ihr Veröffentlichungsdatum und die Versionshinweise. Nach einem Klick auf „Jetzt aktualisieren“ geht Gately so vor:

1. das Release-Paket für diese Plattform von GitHub herunterladen;
2. die SHA-256 mit der `checksums.txt` desselben Releases abgleichen;
3. die neue Binärdatei testweise starten, um sicherzustellen, dass sie auf diesem Rechner läuft;
4. die ausführbare Datei ersetzen und an Ort und Stelle neu starten; die vorherige Version bleibt als `gately.old` daneben liegen, damit Sie zurückgehen können.

Der Dialog zeigt den aktuellen Schritt sowie Fortschritt und Geschwindigkeit des Downloads, und bis die Binärdatei ersetzt wird, können Sie jederzeit abbrechen. Nach einem Neuladen der Seite wird ein noch laufendes Upgrade weiter angezeigt; bei Fehlern erscheint der Grund mit einer Schaltfläche zum erneuten Versuch.

- **PVE-LXC-Container**: Auch LXC-Container, die aus dem OCI-Image erstellt wurden, lassen sich online aktualisieren, ohne sie zu löschen und neu anzulegen;
- **Update-Proxy**: Ist GitHub aus Ihrem Netz schlecht erreichbar, legen Sie auf der Seite „Über“ oder unter Einstellungen → Netzwerk & Laufzeit einen http-, https- oder socks5-Proxy fest; Update-Prüfung und Download laufen beide darüber;
- **Offline-Upgrade und Zurückgehen**: „Upgrade-Paket hochladen“ akzeptiert ein Release-tar.gz oder die bloße Binärdatei jeder Version und eignet sich daher auch, um zu einer älteren Version zurückzukehren;
- **Nur durch Administratoren ausgelöst**: Gately lädt oder installiert nie von selbst eine Version. Docker-, fnOS- und OpenWrt-Paketinstallationen verweisen auf ihren eigenen Upgrade-Weg.

Siehe [Installation · Online-Upgrade](/de/docs/guide/install#online-upgrade).

## OpenWrt-Pakete

Jedes Release enthält jetzt OpenWrt-Pakete für amd64 / arm64 / arm / mipsle / mips / riscv64:

- OpenWrt 24.10 und älter (auch iStoreOS): `opkg install ./gately_v0.5.4_openwrt_<arch>.ipk`
- OpenWrt 25.12 und neuer: `apk add --allow-untrusted ./gately_v0.5.4_openwrt_<arch>.apk`

Der Dienst wird für den Systemstart aktiviert und direkt nach der Installation gestartet; die Verwaltungsoberfläche ist unter `http://<Router-Adresse>:16680` erreichbar. Die Konfiguration liegt in `/etc/gately` und bleibt bei Upgrades, Deinstallation und Firmware-Upgrades erhalten; für ein Upgrade installieren Sie das neuere Paket. Vor der Installation wird die Gerätearchitektur geprüft, wählen Sie das Paket also anhand von `DISTRIB_ARCH` in `/etc/openwrt_release`. Die Binärdatei ist etwa 35 MB groß und passt zu x86-Soft-Routern, ARM64-Boxen und anderen Geräten mit reichlich Speicher.

Siehe [Installation · OpenWrt](/de/docs/guide/install#openwrt).

## Fehlerbehebungen

- Das Speichern von Einstellungen trennt eine Verwaltungsoberfläche, die über Gately selbst erreicht wird, nicht mehr ab: Beim Bearbeiten einer Regel der Portweiterleitung werden Ziele und SNI-Routen an Ort und Stelle ausgetauscht und bestehende Verbindungen gehalten, solange Listen-Ports, Protokolle, Modus und Limits gleich bleiben. Das Speichern von Einstellungen der Portweiterleitung oder der Web-Dienste startet nicht mehr alle Listener neu.
- Die WAF stuft JSON-Feldnamen wie `credentials` oder `forwardAuth` nicht mehr als Zugriff auf Systemdateien ein; das führte beim Speichern von DDNS-Aufgaben oder beim Hinzufügen von Listenern der Web-Dienste zu 403.
- Listeneingaben wie Domains, IP-Listen, Header und STUN-Server verschlucken beim Tippen keine Eingabetaste, Kommas und Leerzeichen mehr.
- mips- / mipsle-Binärdateien werden jetzt mit Soft-Float gebaut und laufen damit auf Routern ohne Hardware-FPU.
- Der Versionsvergleich folgt jetzt semver, sodass neueren Builds kein „Upgrade“ auf eine ältere Version mehr angeboten wird.

## Upgrade

- Online-Upgrades gibt es ab v0.5.4, dieses eine Upgrade erfolgt also noch manuell: Binärdatei ersetzen und neu starten, das neue Docker-Image laden und den Container neu erstellen oder die neue `.fpk` im fnOS App Center installieren. Danach können Sie auf der Seite „Über“ aktualisieren.
- Haben Sie Gately auf OpenWrt von Hand eingerichtet, installieren Sie die `.ipk` / `.apk` darüber; die Konfiguration in `/etc/gately` funktioniert weiter.
