# Gately v0.5.9 veröffentlicht

26. Oktober 2026

Diese Version verwaltet File Browser ([#23](https://github.com/wangwanjie/gately/issues/23)), stellt IP-Adress-Zertifikate aus ([#24](https://github.com/wangwanjie/gately/issues/24)) und macht alle verwalteten externen Programme online installier- und zurücksetzbar.

[v0.5.9 herunterladen](/de/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9)

## File Browser

Die Gruppe „Dateidienste“ erhält eine Seite „File Browser“, die den Web-Dateimanager [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser) verwaltet. Das ursprüngliche filebrowser/filebrowser wurde 2026 archiviert und erhält keine Sicherheitskorrekturen mehr, daher setzt Gately auf den weiter gepflegten Quantum-Fork.

- Jede Instanz hat eine Lauschadresse und einen Port, einen Basispfad für Reverse-Proxys nach Pfad, ein oder mehrere freigegebene Verzeichnisse (jeweils auch schreibgeschützt), die Oberflächensprache und die Gültigkeitsdauer der Anmeldung;
- Angemeldet wird per Benutzername und Passwort, über einen Benutzernamen-Header eines Reverse-Proxys (passend zur Web-Authentifizierung des Web-Dienstes) oder gar nicht (mit deutlicher Warnung);
- Das Admin-Passwort wird File Browser über eine Umgebungsvariable übergeben, bei jedem Start synchronisiert und nie in eine Datei geschrieben;
- Eine Instanz, deren freigegebenes Verzeichnis fehlt, startet nicht. Beim Löschen einer Instanz wird ihr Datenverzeichnis (Benutzer, Freigabelinks, Caches) mitgelöscht, die Dateien in den freigegebenen Verzeichnissen bleiben unberührt.

Siehe [Dateidienste](/de/docs/modules/tools).

## IP-Adress- und kurzlebige Zertifikate

ACME-Zertifikate erhalten ein „Zertifikatsprofil“: die Vorgabe der CA, das kurzlebige Profil von Let's Encrypt (etwa 6 Tage) oder einen anderen Profilnamen, den die CA unterstützt.

- Öffentliche IPv4- und IPv6-Adressen lassen sich direkt in die Domainliste eintragen, um ein IP-Adress-Zertifikat zu erhalten. IP-Zertifikate brauchen die HTTP-01-Validierung und bei Let's Encrypt das kurzlebige Profil; der Editor weist darauf hin und stellt es mit einem Klick ein;
- Voreingestellte CAs stellen nur für öffentliche Adressen aus, private, Loopback- und 100.64.0.0/10-Adressen werden abgelehnt; eine eigene CA (etwa step-ca) hat diese Grenzen nicht, braucht aber weiterhin HTTP-01;
- TLS-Verbindungen ohne SNI (Zugriff per IP) erhalten automatisch das IP-Zertifikat, das zur lokalen Adresse passt;
- Kurzlebige Zertifikate werden um die eingestellten „Vorlaufstunden für kurzlebige Zertifikate“ vor dem Ablauf erneuert (standardmäßig 24, höchstens 80) und nach einem Fehlschlag stündlich erneut versucht; Zertifikatskarten zeigen das Tag „Kurzlebig“ und die verbleibenden Stunden.

Siehe [SSL-Zertifikate](/de/docs/modules/ssl).

## Online-Installation verwalteter Programme

Die Seiten von frp, cloudflared, Tailscale und File Browser erhalten die Karte „Online installieren“:

- Installiert wird die neueste stabile Version oder eine angegebene Version (auch zum Downgrade). Der Download wird gegen seine SHA-256 geprüft und auf diesem Rechner probeweise ausgeführt, bevor er etwas ersetzt, und die Prozesse, die das Programm nutzen, starten neu;
- Jedes Programm kann einen eigenen Download-Proxy haben (http, https, socks5); leer bedeutet, dass der globale „Update-Proxy“ gilt;
- Ersetzte Versionen bleiben in `bin/.versions/` unter dem Konfigurationsverzeichnis, höchstens 3, und lassen sich mit einem Klick zurückholen oder löschen;
- „Deinstallieren“ löscht das installierte Programm und alle früheren Versionen und behält die Moduleinstellungen;
- „Standardeinstellungen wiederherstellen“ im Seitenkopf stoppt die Prozesse und setzt die Moduleinstellungen zurück, die alten Einstellungen bleiben im Konfigurationsverlauf;
- Die Online-Installation von Tailscale gibt es nur unter Linux, da es für macOS und Windows keine offiziellen statischen Pakete gibt.

Programme werden jetzt zuerst im auf der Seite gesetzten Pfad, dann in `bin/` unter dem Konfigurationsverzeichnis und dann in `PATH` gesucht, sodass online installierte Programme wirksam werden. Siehe [Vernetzung & Tunnel](/de/docs/modules/tunnels).

## Gemeinsame Benutzer der Dateidienste

Die gemeinsamen Benutzer von WebDAV, FTP und SMB werden jetzt auf der eigenen Seite „Dateidienste → Gemeinsame Dateibenutzer“ bearbeitet. Sie zeigt für jeden Dienst, ob er aktiviert ist und gemeinsame Benutzer zulässt, und welche gemeinsamen Benutzer von einem gleichnamigen lokalen Benutzer überdeckt werden. Auf den Dienstseiten bleibt nur der Schalter „Gemeinsame Benutzer erlauben“. Der neue Endpunkt `GET/PUT /api/fileusers` kommt mit den Token-Berechtigungen `fileusers:read` und `fileusers:write`, die bisherigen Endpunkte `/api/<dienst>/shared-users` funktionieren weiter.

## Hinweise zum Upgrade

- So aktualisieren Sie: Linux-Binärinstallationen werden auf der Seite Über aktualisiert; bei Docker das neue Image ziehen und den Container neu erstellen; auf fnOS das neue `.fpk` im App-Center installieren; auf OpenWrt das neue `.ipk` / `.apk` installieren.
- Das Konfigurationsformat ist abwärtskompatibel, und vorhandene Zertifikate werden durch das Upgrade nicht neu ausgestellt.
- Mit der neuen Suchreihenfolge wird ein gleichnamiges Programm in `bin/` unter dem Konfigurationsverzeichnis vor dem in `PATH` verwendet.
- Unter „Module“ ausgeschaltete Dateidienste blockieren Änderungen an den gemeinsamen Benutzern nicht mehr.
