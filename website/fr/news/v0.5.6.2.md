# Gately v0.5.6.2 est disponible

23 octobre 2026

Il s'agit d'une version corrective de la série v0.5.6. Toutes les installations devraient mettre à jour.

[Télécharger v0.5.6.2](/fr/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.2)

## Docker 29 fonctionne dans le module Docker

Depuis Docker 25, la version minimale d'API augmente, et Docker 29 exige au moins 1.44. Gately utilisait toujours 1.41, d'où le message d'échec de connexion sur la page Docker. Gately lit désormais la plage prise en charge à la première connexion : il garde 1.41 si le démon la prend en charge, utilise sinon la version minimale du démon, et la version propre du moteur avant 20.10.

## Sans session, accès direct à la page de connexion

La session est stockée dans un cookie illisible par la page : sans session, l'interface affichait la vue d'ensemble jusqu'à ce qu'un appel d'API renvoie 401 et redirige. La session est maintenant vérifiée avant d'afficher une page ; sans session, la page de connexion s'affiche directement, puis on revient à la page demandée.

## Cloudflare accepte les configurations importées de Lucky

Lucky n'utilise que le jeton d'API Cloudflare, et les configurations importées gardent souvent dans le champ ID l'AccessKey d'un autre fournisseur. Gately la prenait pour l'e-mail du compte et passait à la Global API Key, si bien que le DDNS et la validation des certificats échouaient avec 6003 Invalid request headers. La Global API Key n'est plus utilisée que si l'ID est un e-mail ; sinon le jeton d'API est utilisé.

## Les enregistrements DDNS renommés se synchronisent aussitôt

Lors de la modification d'une tâche, les enregistrements dont le domaine, le type, la ligne ou le TTL changeaient gardaient l'ancien état et passaient pour synchronisés, donc le nouvel enregistrement DNS n'était jamais créé. Ils sont désormais resynchronisés à l'enregistrement.

## Notes de mise à jour

- Docker : récupérez la nouvelle image et recréez le conteneur. Les autres installations peuvent se mettre à jour en ligne depuis les Paramètres ou en installant le nouveau paquet.
- Les tâches dont vous avez vidé l'ID Cloudflare à la main à cause de l'erreur 6003 n'ont pas besoin d'être rétablies.
