# Gately v0.5.9.1 est disponible

26 octobre 2026

Il s'agit d'une mise à jour de la série v0.5.9, issue de la suggestion de [issue #25](https://github.com/wangwanjie/gately/issues/25), qui corrige aussi deux éditeurs qui ne pouvaient pas enregistrer.

[Télécharger v0.5.9.1](/fr/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9.1)

## HTTP et HTTPS sur le même port

Les écouteurs avec HTTPS disposent de l'option « HTTP sur le même port », réglée sur « Refuser » par défaut. Avec « Rediriger vers HTTPS », `http://hôte:port` est redirigé vers `https://hôte:port` (301 pour GET et HEAD, 308 pour les autres méthodes afin de conserver la méthode et le corps) ; avec « Servir », les sites répondent en HTTP non chiffré. C'est utile quand un seul port peut être redirigé et que les visiteurs peuvent se tromper de schéma, par exemple sur un port non standard d'une connexion domestique.

Gately distingue TLS et HTTP grâce au premier octet de chaque connexion. Les en-têtes du protocole PROXY sont toujours lus avant, la négociation HTTP/2 et les défis ACME HTTP-01 fonctionnent toujours, et `Alt-Svc` n'est envoyé qu'en HTTPS. À l'import d'une configuration nginx, `error_page 497 https://$host:$server_port$request_uri` dans un server HTTPS devient « Rediriger vers HTTPS ». Voir [Service web](/fr/docs/modules/web).

## URL d'accès de File Browser

Une instance File Browser peut avoir plusieurs URL d'accès, comme `https://files.example.com/` publiée par le proxy inverse du Service web. La carte de l'instance les affiche ; si la liste est vide, l'adresse est toujours déduite de l'adresse et du port d'écoute. Le schéma, l'hôte et le port de la première URL deviennent l'URL externe de File Browser, utilisée par les liens de partage. Voir [Services de fichiers](/fr/docs/modules/tools#filebrowser).

## Corrections

- L'enregistrement d'une instance File Browser modifiée échouait avec `json: unknown field "state"`. Corrigé.
- L'enregistrement d'un tunnel Cloudflare modifié échouait avec la même erreur `json: unknown field "state"`. Corrigé.
- Avec les utilisateurs partagés activés, les journaux d'écoute FTP et WebDAV affichaient 0 utilisateur ([issue #26](https://github.com/wangwanjie/gately/issues/26)). Ils indiquent désormais « N utilisateurs, dont M partagés » comme SMB, et WebDAV consigne les nouveaux totaux quand les utilisateurs partagés changent.

## Notes de mise à jour

- « HTTP sur le même port » est désactivé par défaut, les écouteurs existants se comportent donc comme avant. Le modifier redémarre l'écouteur et coupe ses connexions ouvertes.
- Avec « Servir », les sites consultés en HTTP ne sont pas chiffrés et les mots de passe de l'authentification web et des utilisateurs partagés circulent aussi en clair. Pour un accès depuis Internet, utilisez « Rediriger vers HTTPS ».
