# Gately v0.5.3 est disponible

21 octobre 2026

Cette version est consacrée à fnOS. Gately s'installe désormais comme une application native fnOS : il s'ouvre depuis l'icône du bureau fnOS, utilise le point d'entrée que vous utilisez déjà pour fnOS, et les administrateurs fnOS n'ont plus besoin de se connecter une seconde fois. Vous pouvez aussi désactiver des modules fonctionnels entiers dont vous ne vous servez pas.

[Télécharger la v0.5.3](/fr/download#fnos) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.3)

## Application native fnOS

Chaque version fournit des paquets fnOS hors ligne, `gately_0.5.3_fnos_x86.fpk` (Intel / AMD) et `gately_0.5.3_fnos_arm.fpk` (ARM). Installez-les depuis « Centre d'applications → Installation manuelle » dans fnOS.

- **S'intègre à la passerelle unifiée fnOS** : cliquez sur l'icône du bureau et l'interface d'administration s'ouvre sous `/app/gately/`, sur le même point d'entrée que fnOS. L'adresse du réseau local comme votre domaine fnOS distant fonctionnent, sans avoir à ouvrir ni rediriger le port 16680. L'accès via la passerelle est contrôlé par fnOS, et seuls les administrateurs fnOS peuvent l'ouvrir.
- **Connecte les administrateurs fnOS avec leur session fnOS** : activez « Connexion via fnOS » dans « Paramètres → Contrôle d'accès » et les administrateurs déjà connectés à fnOS entrent directement dans Gately, sans mot de passe ni code à deux facteurs. Les utilisateurs fnOS ordinaires doivent toujours se connecter. Après une déconnexion, la page de connexion affiche un bouton « Se connecter avec le compte fnOS &lt;nom&gt; » au lieu de vous reconnecter silencieusement. Ce réglage est désactivé par défaut.
- **Toutes les fonctions** : l'application s'exécute en root ; elle peut donc écouter sur 80/443, gérer Docker et ouvrir le terminal Web. La configuration est conservée à la désinstallation, et la mise à niveau consiste à installer le `.fpk` plus récent.

Voir [Installation · Application native fnOS](/fr/docs/guide/install#fnos) pour les détails.

## Activation des modules fonctionnels

« Paramètres → Modules » permet de désactiver un module entier. Un module désactivé charge toujours sa configuration, mais ne démarre aucun service, ne sert aucune API d'administration (ses points de terminaison renvoient 403) et est masqué dans l'interface ; sa configuration est conservée et revient quand vous le réactivez. Les modules dont d'autres dépendent ne peuvent pas être désactivés, et les changements prennent effet après un redémarrage. Si vous n'utilisez que quelques fonctions, cela réduit le nombre de services en écoute et de points de terminaison appelables.

## Autres améliorations

- L'interface d'administration regroupe désormais les traductions de chaque langue dans un seul fichier, ce qui fait passer les requêtes du premier chargement d'environ 170 à environ 75, et recharge la page une fois quand une page ou une feuille de style chargée à la demande échoue.
- La documentation de l'API décrit l'activation des modules et les champs de réglages liés à fnOS.

## Mise à niveau

- Docker : récupérez la nouvelle image et recréez le conteneur. Binaire : remplacez l'exécutable et redémarrez.
- L'application native fnOS et l'image Docker utilisent toutes deux le port 16680. Avant de passer de l'image Docker à l'application native, arrêtez le conteneur `gately` et copiez votre répertoire de configuration dans le `var/config` de l'application.
