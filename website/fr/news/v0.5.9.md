# Gately v0.5.9 est disponible

26 octobre 2026

Cette version gère File Browser ([#23](https://github.com/wangwanjie/gately/issues/23)), émet des certificats d'adresse IP ([#24](https://github.com/wangwanjie/gately/issues/24)) et permet d'installer et de restaurer en ligne tous les programmes externes gérés.

[Télécharger v0.5.9](/fr/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9)

## File Browser

Le groupe « Services de fichiers » gagne une page « File Browser » qui gère le gestionnaire de fichiers web [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser). Le projet d'origine filebrowser/filebrowser a été archivé en 2026 et ne reçoit plus de correctifs de sécurité, Gately utilise donc le fork Quantum, toujours maintenu.

- Chaque instance a une adresse et un port d'écoute, un chemin de base pour un proxy inverse par chemin, un ou plusieurs répertoires partagés (chacun peut être en lecture seule), la langue de l'interface et la durée de session ;
- La connexion se fait par nom d'utilisateur et mot de passe, par un en-tête de nom d'utilisateur transmis par un proxy inverse (à combiner avec l'authentification Web du Service Web), ou sans connexion (avec un avertissement bien visible) ;
- Le mot de passe administrateur est transmis à File Browser par une variable d'environnement, synchronisé à chaque démarrage et jamais écrit dans un fichier ;
- Une instance dont le répertoire partagé n'existe pas refuse de démarrer, et supprimer une instance supprime son répertoire de données (utilisateurs, liens de partage, caches) sans toucher aux fichiers des répertoires partagés.

Voir [Services de fichiers](/fr/docs/modules/tools).

## Certificats d'adresse IP et de courte durée

Les certificats ACME gagnent un « Profil de certificat » : celui par défaut de la CA, le profil de courte durée de Let's Encrypt (environ 6 jours) ou tout autre nom de profil pris en charge par la CA.

- Des adresses IPv4 et IPv6 publiques peuvent être saisies directement dans la liste des domaines pour obtenir un certificat d'adresse IP. Les certificats IP exigent la validation HTTP-01 et, avec Let's Encrypt, le profil de courte durée ; l'éditeur le signale et le configure en un clic ;
- Les CA prédéfinies n'émettent que pour des adresses publiques, les adresses privées, de bouclage et de 100.64.0.0/10 sont donc refusées ; une CA personnalisée (comme step-ca) n'a aucune de ces limites mais exige toujours HTTP-01 ;
- Les connexions TLS sans SNI (accès par IP) reçoivent automatiquement le certificat IP correspondant à l'adresse locale ;
- Les certificats de courte durée sont renouvelés selon les « Heures d'avance pour les certificats de courte durée » (24 par défaut, 80 au maximum) et réessayés toutes les heures après un échec ; les cartes de certificat affichent l'étiquette « Courte durée » et les heures restantes.

Voir [Certificats SSL](/fr/docs/modules/ssl).

## Installation en ligne des programmes gérés

Les pages frp, cloudflared, Tailscale et File Browser gagnent une carte « Installation en ligne » :

- Installer la dernière version stable ou une version donnée (y compris pour revenir en arrière). Le téléchargement est vérifié avec son SHA-256 et testé sur cette machine avant de remplacer quoi que ce soit, puis les processus qui utilisent le programme redémarrent ;
- Chaque programme peut avoir son propre proxy de téléchargement (http, https, socks5) ; vide, c'est le « Proxy de mise à jour » global qui s'applique ;
- Les versions remplacées sont conservées dans `bin/.versions/` sous le répertoire de configuration, 3 au maximum, et peuvent être restaurées ou supprimées en un clic ;
- « Désinstaller » supprime le programme installé et toutes les versions précédentes, et conserve les réglages du module ;
- « Rétablir les valeurs par défaut » dans l'en-tête de la page arrête les processus et réinitialise les réglages du module, les anciens réglages étant conservés dans l'historique de configuration ;
- L'installation en ligne de Tailscale est réservée à Linux, faute de paquets statiques officiels pour macOS et Windows.

Les programmes sont désormais recherchés dans le chemin indiqué sur la page, puis dans `bin/` sous le répertoire de configuration, puis dans `PATH`, de sorte que les programmes installés en ligne sont pris en compte. Voir [Réseaux et tunnels](/fr/docs/modules/tunnels).

## Utilisateurs partagés des services de fichiers

Les utilisateurs partagés de WebDAV, FTP et SMB se modifient désormais sur une page dédiée, « Services de fichiers → Utilisateurs partagés de fichiers », qui indique pour chaque service s'il est activé et s'il autorise les utilisateurs partagés, ainsi que les utilisateurs partagés masqués par un utilisateur local du même nom. Les pages des services ne gardent que l'interrupteur « Autoriser les utilisateurs partagés ». Le nouveau point d'accès `GET/PUT /api/fileusers` s'accompagne des permissions de jeton `fileusers:read` et `fileusers:write`, et les anciens points d'accès `/api/<service>/shared-users` continuent de fonctionner.

## Notes de mise à jour

- Comment mettre à jour : les installations par binaire Linux se mettent à jour depuis la page À propos ; avec Docker, récupérez la nouvelle image et recréez le conteneur ; sur fnOS, installez le nouveau `.fpk` depuis le centre d'applications ; sur OpenWrt, installez le nouveau `.ipk` / `.apk`.
- Le format de configuration est rétrocompatible, et les certificats existants ne sont pas réémis par la mise à jour.
- Avec le nouvel ordre de recherche, un programme du même nom dans `bin/` sous le répertoire de configuration est utilisé avant celui de `PATH`.
- Les services de fichiers désactivés dans « Modules » ne bloquent plus la modification des utilisateurs partagés.
