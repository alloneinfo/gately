# Gately v0.5.0 发布

2026 年 10 月 19 日

Gately 运行在网络边界，手握 DNS 密钥和证书私钥，所以“看得见”一直是第一原则。v0.5.0 把这条原则从“代码开源”延伸到了“运行可追溯”：谁在什么时候改了什么、配置怎么变的、下载的程序是不是官方构建，现在都能查得清楚。

[下载 v0.5.0](/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.0)

## 可追溯：操作审计与配置历史

- **操作审计**：登录、每一次配置变更、下载备份或证书私钥、打开终端，都会记录操作者、来源 IP、方法与路径。不记录请求体，也不记录任何密钥。
- **配置历史与一键回滚**：每次覆盖配置文件前自动保存旧版本，每个配置保留 30 个，可以逐行对比后回滚；回滚本身也能撤销。
- **真实来源**：管理界面放在本机 nginx、haproxy 或 Gately Web 服务之后时，只信任本机代理传来的地址，仅内网访问、登录限流和审计日志都能看到真实访问者。

详见 [审计与配置历史](/docs/guide/audit)。

## 更安全的登录

- **Passkey 登录**：用指纹、面容或设备 PIN 代替密码，只保存公钥，无需再输入两步验证码。
- **只读账号**：给家人或同事一个只能查看的账号，不能修改配置、下载备份或读取密钥。
- **签名发布**：二进制和 Docker 镜像带有 cosign 签名、构建来源证明与 SBOM，可以确认下载的就是官方 CI 构建，方法见 [校验发布产物](/docs/guide/verify)。

## 新功能

- **ACME HTTP-01**：没有受支持 DNS 服务商时也能自动签发证书。
- **HTTP/3（QUIC）**：Web 服务监听一键开启。
- **端口转发发送 PROXY 协议**：经 haproxy、nginx 多层转发时保留真实客户端地址，详见 [端口转发](/docs/modules/portforward)。
- **DDNS 新增 7 家**：Amazon Route 53、OVHcloud、Gandi、NS1、Bunny DNS、Namecheap、DynDNS2（No-IP、Dynu 等）。
- **通知新增 7 个渠道**：ntfy、Gotify、Pushover、Discord、Slack、Server酱、PushPlus，并内置“关键故障”“证书到期”“安全与登录”等规则模板。

## 更省心的运维

- **全局 Prometheus 指标** `/api/metrics`：证书剩余天数、DDNS 同步状态、端口转发流量、站点与后端健康一处抓取，附 Grafana 面板，见 [监控指标](/docs/reference/monitoring)。
- **网络自检**：一键检查公网 IPv4 / IPv6、运营商 NAT、系统时间、80 / 443 端口、DDNS 解析与证书到期。
- **首次启动引导**：改密码、两步验证 / Passkey、自检、从 Lucky 导入、通知设置一页走完。
- **部署**：`GATELY_INITIAL_PASSWORD` 指定初始密码，`-apply` 声明式配置目录便于 GitOps，新增 systemd 与 OpenWrt 服务模板，见 [安装部署](/docs/guide/install)。

## 升级提示

- Docker：拉取新镜像后重建容器即可；二进制：替换可执行文件后重启。
- 端口转发开启 PROXY 协议后，目标（例如 haproxy 的 `accept-proxy`）必须接收它。若要降级到 v0.4.x，请先撤掉目标上的 PROXY 接收配置。
- 信任本机代理默认开启，可在「设置 → 访问限制」关闭。
- 由于加入 QUIC，单文件体积约 32 MB。
