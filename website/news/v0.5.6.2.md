# Gately v0.5.6.2 发布

2026 年 10 月 23 日

这是 v0.5.6 系列的修复版本，所有部署方式都建议升级。

[下载 v0.5.6.2](/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.2)

## Docker 29 下可以正常管理容器

Docker 25 起逐步提高了支持的最低 API 版本，Docker 29 要求至少 1.44，而 Gately 固定使用 1.41，Docker 管理页因此提示无法连接。现在 Gately 首次连接时读取 Docker 的版本范围：支持 1.41 时继续使用 1.41，不支持时改用 Docker 的最低版本，20.10 之前的旧版 Docker 则使用其自身版本。

## 未登录时直接进入登录页

会话保存在浏览器无法读取的 Cookie 中，之前未登录打开管理界面会先渲染总览页，等接口返回 401 才跳到登录页，出现一闪而过的主界面。现在进入页面前先确认登录状态，未登录时直接显示登录页，登录后回到原本要打开的页面。

## Cloudflare 兼容 Lucky 导入的配置

Lucky 的 Cloudflare 只使用 API Token，导入的配置里「ID」字段常残留其他服务商的 AccessKey，Gately 把它当作账号邮箱改用 Global API Key 认证，DDNS 与证书验证因此报错 6003 Invalid request headers。现在只有 ID 是邮箱时才使用 Global API Key，其余情况按 API Token 认证。

## DDNS 记录改名后立即同步

修改任务时，改了域名、类型、线路或 TTL 的记录会沿用改名前的同步状态，被当作已同步而不创建新的解析。现在这些记录会在保存后重新同步。

## Web 服务登录页与错误页重新设计

开启网页认证的站点登录页、404 与 502 错误页，以及管理后台输错安全入口时的提示页，换成统一的卡片式设计，随系统自动切换浅色与深色。两步验证改为弹窗：输入用户名和密码后，需要动态验证码时在原页面弹出验证码框，输满 6 位自动提交；之前需要验证码时会清空已填的用户名和密码，现在不必重新输入，密码输错时也会保留用户名。命令行、接口等非浏览器请求仍返回原来的纯文本。

## 升级提示

- Docker 拉取新镜像后重建容器；其他部署方式可在「系统设置」中在线升级，或下载对应安装包覆盖安装。
- 之前因 6003 报错手动清空过 Cloudflare ID 的任务无需改回。
