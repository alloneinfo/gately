# Gately v0.5.9.1 发布

2026 年 10 月 26 日

这是 v0.5.9 系列的更新，来自 [issue #25](https://github.com/wangwanjie/gately/issues/25) 的建议，并修复了两处编辑后无法保存的问题。

[下载 v0.5.9.1](/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9.1)

## HTTP 与 HTTPS 共用同一端口

开启 HTTPS 的监听新增「同端口 HTTP」选项，默认「不接受」。选「跳转到 HTTPS」时，访问 `http://域名:端口` 会跳转到 `https://域名:端口`（GET、HEAD 用 301，其他方法用 308，保留请求方法与请求体）；选「直接服务」时按明文 HTTP 提供站点。适合只能映射一个端口、又希望访客输错协议也能打开的场景，例如家宽的非标准端口。

Gately 按每个连接的第一个字节区分 TLS 与 HTTP，PROXY 协议头仍然先于协议识别解析，HTTP/2 协商、ACME HTTP-01 验证照常工作，`Alt-Svc` 只在 HTTPS 响应中发送。导入 nginx 配置时，HTTPS server 中的 `error_page 497 https://$host:$server_port$request_uri` 会转换为「跳转到 HTTPS」。详见 [Web 服务](/docs/modules/web)。

## File Browser 访问地址

File Browser 实例可以填写多个访问地址，例如经 Web 服务反向代理的 `https://files.example.com/`，实例卡片显示这些地址，留空时仍按监听地址和端口推测。第一个地址的协议、主机与端口写入 File Browser 的外部地址，分享链接使用该地址。详见 [文件服务](/docs/modules/tools#filebrowser)。

## 修复

- 编辑已有的 File Browser 实例后保存提示 `json: unknown field "state"`，现已修复。
- 编辑已有的 Cloudflare 隧道后保存同样提示 `json: unknown field "state"`，现已修复。
- 开启共享用户后，FTP 与 WebDAV 的监听日志把用户数显示为 0（[issue #26](https://github.com/wangwanjie/gately/issues/26)）。现在与 SMB 一样显示「N 个用户，其中 M 个共享用户」，WebDAV 在共享用户变化后会记录新的数量。

## 升级提示

- 「同端口 HTTP」默认关闭，升级后已有监听的行为不变；修改此项会重启该监听，已有连接会断开。
- 「直接服务」下站点经明文 HTTP 访问时不加密，网页认证、共享用户登录等密码也以明文传输，公网访问建议用「跳转到 HTTPS」。
