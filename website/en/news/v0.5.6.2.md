# Gately v0.5.6.2 released

October 23, 2026

This is a fix release in the v0.5.6 series. All installs should upgrade.

[Download v0.5.6.2](/en/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.2)

## Docker 29 works in the Docker module

Docker 25 started raising the minimum supported API version, and Docker 29 requires at least 1.44. Gately always used 1.41, so the Docker page reported that it could not connect. Gately now reads the supported range on first connect: it keeps 1.41 when the daemon supports it, moves to the daemon's minimum when it does not, and uses the daemon's own version on engines older than 20.10.

## Signed-out visits go straight to the login page

The session lives in a cookie the page cannot read, so opening the admin UI without a session rendered the overview until an API call returned 401 and redirected to login. The UI now checks the session before showing a page, goes straight to the login page when signed out, and returns to the requested page after sign-in.

## Cloudflare accepts configurations imported from Lucky

Lucky's Cloudflare integration only uses the API token, and imported configurations often keep another provider's AccessKey in the ID field. Gately treated it as the account email and switched to Global API Key auth, so DDNS and certificate validation failed with 6003 Invalid request headers. Global API Key auth is now used only when the ID is an email; otherwise the API token is used.

## Renamed DDNS records sync right away

When a task was edited, records whose domain, type, line or TTL changed kept the old sync state and were treated as already synced, so the new DNS record was never created. Such records now sync again after saving.

## Redesigned Web service login and error pages

The login page of sites with web authentication, the 404 and 502 error pages, and the page shown for a wrong security entrance of the admin console now share one card design that follows the system light or dark theme. Two-step verification moves to a popup: after the username and password are accepted, a code dialog opens on the same page and submits once 6 digits are entered. Previously the username and password were cleared when a code was required; now nothing has to be typed again, and a wrong password keeps the username. Non-browser requests such as the CLI or API calls still get the plain-text responses.

## Upgrade notes

- Docker: pull the new image and recreate the container. Other installs can upgrade online in Settings or by installing the new package.
- Tasks whose Cloudflare ID you cleared by hand because of the 6003 error do not need to be changed back.
