# Gately v0.5.6.3 released

October 23, 2026

This is a fix release in the v0.5.6 series, mainly for router systems such as OpenWrt, ImmortalWrt and iStoreOS. Other installs can upgrade when convenient.

[Download v0.5.6.3](/en/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.3)

## The overview shows OpenWrt's br-lan

The overview hides Docker and other virtual interfaces, and the `br-` prefix in that rule also hid OpenWrt's LAN bridge `br-lan`. On a bypass router the LAN IPv4 and the public IPv6 both live on `br-lan`, so the overview showed no addresses at all. Only Docker network bridges (`br-` plus 12 hex digits) are hidden now, and `br-lan` and `br-wan` are listed. DDNS and STUN could always pick `br-lan` when reading addresses from an interface.

## The system time zone is used on OpenWrt

OpenWrt has neither `/etc/localtime` nor `/usr/share/zoneinfo`, and procd does not pass `TZ` to services, so Gately always ran in UTC: log and notification times were hours off, and zones such as `Asia/Shanghai` were rejected as invalid in Settings. The time zone database is now built in, so every zone can be saved in Settings. When no zone is set, Gately uses the one configured for the system (`zonename` in `/etc/config/system`, or `/etc/TZ` when that is missing), matching what LuCI shows.

## Upgrade notes

- OpenWrt packages: install the new `.apk` or `.ipk` over the old one, or check for updates in Settings.
- `zoneinfo-*` packages you installed to fix the time can stay or be removed.
- After changing the system time zone in LuCI, restart Gately for it to take effect. A zone set in Gately's Settings takes priority over the system zone.
