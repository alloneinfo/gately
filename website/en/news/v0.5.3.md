# Gately v0.5.3 released

October 21, 2026

This release is about fnOS. Gately now installs as a native fnOS app: it opens from the fnOS desktop icon, uses the entry point you already use for fnOS, and fnOS administrators no longer need to sign in a second time. You can also turn off whole feature modules you do not use.

[Download v0.5.3](/en/download#fnos) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.3)

## Native fnOS app

Every release ships offline fnOS packages, `gately_0.5.3_fnos_x86.fpk` (Intel / AMD) and `gately_0.5.3_fnos_arm.fpk` (ARM). Install them from "App Center → Manual install" in fnOS.

- **Works with the fnOS unified gateway**: click the desktop icon and the admin UI opens under `/app/gately/`, sharing the entry point you use for fnOS. Both the LAN address and your remote fnOS domain work, with no need to open or forward port 16680. Access through the gateway is controlled by fnOS, and only fnOS administrators can open it.
- **Signs fnOS administrators in with their fnOS session**: turn on "Sign in with fnOS" under "Settings → Access control" and administrators already signed in to fnOS go straight into Gately, without a password or two-step code. Regular fnOS users still sign in. After you sign out, the login page shows a "Sign in as fnOS user &lt;name&gt;" button instead of signing you back in silently. The setting is off by default.
- **Every feature**: the app runs as root, so it can listen on 80/443, manage Docker and open the Web terminal. Config is kept on uninstall, and upgrading is installing the newer `.fpk`.

See [Installation · fnOS native app](/en/docs/guide/install#fnos) for details.

## Feature module switches

"Settings → Modules" can turn off a whole module. A disabled module still loads its configuration but starts no services, serves no admin API (its endpoints return 403) and is hidden from the UI; its configuration is kept and comes back when you turn it on again. Modules that others depend on cannot be turned off, and changes take effect after a restart. If you only use a few features, this reduces listening services and callable endpoints.

## Other improvements

- The admin UI now bundles each language's translations into one file, cutting first-load requests from about 170 to about 75, and reloads once when a lazy-loaded page or stylesheet fails to load.
- The API docs describe the module switches and the fnOS-related settings fields.

## Upgrading

- Docker: pull the new image and recreate the container. Binary: replace the executable and restart.
- The native fnOS app and the Docker image both use port 16680. Before moving from the Docker image to the native app, stop the `gately` container and copy your config directory to the app's `var/config`.
