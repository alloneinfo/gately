# Gately v0.5.9 lançado

26 de outubro de 2026

Esta versão gerencia o File Browser ([#23](https://github.com/wangwanjie/gately/issues/23)), emite certificados de endereço IP ([#24](https://github.com/wangwanjie/gately/issues/24)) e permite instalar e reverter online todos os programas externos gerenciados.

[Baixar v0.5.9](/pt-BR/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9)

## File Browser

O grupo "Serviços de arquivos" ganha uma página "File Browser" que gerencia o gerenciador de arquivos web [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser). O projeto original filebrowser/filebrowser foi arquivado em 2026 e não recebe mais correções de segurança, por isso o Gately usa o fork Quantum, que continua mantido.

- Cada instância tem endereço e porta de escuta, um caminho base para proxy reverso por caminho, um ou mais diretórios compartilhados (cada um pode ser somente leitura), o idioma da interface e a duração da sessão;
- O login é por usuário e senha, por um cabeçalho de nome de usuário enviado por um proxy reverso (para usar com a autenticação web do Serviço Web) ou sem login (com um aviso bem visível);
- A senha de administrador é passada ao File Browser por uma variável de ambiente, sincronizada a cada inicialização e nunca gravada em arquivo;
- Uma instância cujo diretório compartilhado não existe não inicia, e excluir uma instância exclui seu diretório de dados (usuários, links de compartilhamento, caches) sem afetar os arquivos dos diretórios compartilhados.

Veja [Serviços de arquivos](/pt-BR/docs/modules/tools).

## Certificados de endereço IP e de curta duração

Os certificados ACME ganham um "Perfil do certificado": o padrão da CA, o perfil de curta duração do Let's Encrypt (cerca de 6 dias) ou qualquer outro nome de perfil aceito pela CA.

- Endereços IPv4 e IPv6 públicos podem ser digitados direto na lista de domínios para obter um certificado de endereço IP. Certificados IP exigem validação HTTP-01 e, com o Let's Encrypt, o perfil de curta duração; o editor avisa e configura isso com um clique;
- As CAs predefinidas só emitem para endereços públicos, então endereços privados, de loopback e de 100.64.0.0/10 são recusados; uma CA própria (como o step-ca) não tem nenhum desses limites, mas continua exigindo HTTP-01;
- Conexões TLS sem SNI (acesso por IP) recebem automaticamente o certificado IP correspondente ao endereço local;
- Certificados de curta duração são renovados conforme a "Antecedência para certificados de curta duração (horas)" (24 por padrão, no máximo 80) e tentados de novo a cada hora após uma falha; os cartões de certificado mostram a etiqueta "Curta duração" e as horas restantes.

Veja [Certificados SSL](/pt-BR/docs/modules/ssl).

## Instalação online dos programas gerenciados

As páginas de frp, cloudflared, Tailscale e File Browser ganham um cartão "Instalação online":

- Instale a versão estável mais recente ou uma versão escolhida (inclusive para fazer downgrade). O download é verificado pelo SHA-256 e testado nesta máquina antes de substituir qualquer coisa, e os processos que usam o programa são reiniciados;
- Cada programa pode ter seu próprio proxy de download (http, https, socks5); vazio usa o "Proxy de atualização" global;
- As versões substituídas ficam em `bin/.versions/` no diretório de configuração, no máximo 3, e podem ser restauradas ou excluídas com um clique;
- "Desinstalar" exclui o programa instalado e todas as versões anteriores e mantém as configurações do módulo;
- "Restaurar padrões" no cabeçalho da página para os processos e redefine as configurações do módulo, e as configurações antigas ficam no histórico de configuração;
- A instalação online do Tailscale é só para Linux, pois não há pacotes estáticos oficiais para macOS e Windows.

Agora os programas são procurados no caminho definido na página, depois em `bin/` no diretório de configuração e depois no `PATH`, para que os programas instalados online passem a valer. Veja [Rede e túneis](/pt-BR/docs/modules/tunnels).

## Usuários compartilhados dos serviços de arquivos

Os usuários compartilhados do WebDAV, FTP e SMB agora são editados em uma página própria, "Serviços de arquivos → Usuários compartilhados de arquivos", que mostra para cada serviço se ele está ativado e se permite usuários compartilhados, e quais usuários compartilhados ficam encobertos por um usuário local de mesmo nome. As páginas dos serviços mantêm apenas a chave "Permitir usuários compartilhados". O novo endpoint `GET/PUT /api/fileusers` vem com as permissões de token `fileusers:read` e `fileusers:write`, e os endpoints antigos `/api/<serviço>/shared-users` continuam funcionando.

## Notas de atualização

- Como atualizar: instalações por binário Linux atualizam pela página Sobre; no Docker, baixe a nova imagem e recrie o contêiner; no fnOS, instale o novo `.fpk` pela central de aplicativos; no OpenWrt, instale o novo `.ipk` / `.apk`.
- O formato da configuração é compatível com versões anteriores, e a atualização não reemite os certificados existentes.
- Com a nova ordem de busca, um programa de mesmo nome em `bin/` no diretório de configuração é usado antes do que está no `PATH`.
- Serviços de arquivos desativados em "Módulos" não bloqueiam mais as alterações nos usuários compartilhados.
