# Gately v0.5.3 lançado

21 de outubro de 2026

Esta versão é dedicada ao fnOS. O Gately agora se instala como aplicativo nativo do fnOS: abre pelo ícone na área de trabalho do fnOS, usa o mesmo ponto de entrada que você já usa para o fnOS, e os administradores do fnOS não precisam mais entrar uma segunda vez. Também é possível desativar módulos de recursos inteiros que você não usa.

[Baixar a v0.5.3](/pt-BR/download#fnos) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.3)

## Aplicativo nativo para fnOS

Cada versão inclui pacotes offline para o fnOS, `gately_0.5.3_fnos_x86.fpk` (Intel / AMD) e `gately_0.5.3_fnos_arm.fpk` (ARM). Instale-os em "Central de aplicativos → Instalação manual" no fnOS.

- **Integrado ao gateway unificado do fnOS**: clique no ícone da área de trabalho e a interface de administração abre em `/app/gately/`, compartilhando o ponto de entrada que você usa para o fnOS. Tanto o endereço da rede local quanto o seu domínio remoto do fnOS funcionam, sem precisar abrir ou redirecionar a porta 16680. O acesso pelo gateway é controlado pelo fnOS, e somente administradores do fnOS podem abri-lo.
- **Login de administradores do fnOS pela sessão do fnOS**: ative "Entrar com o fnOS" em "Configurações → Controle de acesso" e os administradores que já estão conectados ao fnOS entram direto no Gately, sem senha nem código de verificação em dois fatores. Os usuários comuns do fnOS continuam fazendo login. Depois que você sai, a página de login mostra um botão "Entrar como usuário do fnOS &lt;nome&gt;" em vez de conectar você de novo silenciosamente. A opção vem desativada por padrão.
- **Todos os recursos**: o aplicativo roda como root, então pode escutar nas portas 80/443, gerenciar o Docker e abrir o Terminal Web. A configuração é mantida na desinstalação, e para atualizar basta instalar o `.fpk` mais novo.

Veja [Instalação · Aplicativo nativo para fnOS](/pt-BR/docs/guide/install#fnos) para mais detalhes.

## Ativar e desativar módulos de recursos

"Configurações → Módulos" pode desativar um módulo inteiro. Um módulo desativado ainda carrega a configuração, mas não inicia serviços, não oferece API de administração (os endpoints retornam 403) e fica oculto na interface; a configuração é mantida e volta quando você o ativa de novo. Módulos dos quais outros dependem não podem ser desativados, e as mudanças valem após reiniciar. Se você usa só alguns recursos, isso reduz os serviços em escuta e os endpoints que podem ser chamados.

## Outras melhorias

- A interface de administração agora junta as traduções de cada idioma em um único arquivo, reduzindo as requisições do primeiro carregamento de cerca de 170 para cerca de 75, e recarrega uma vez quando uma página ou folha de estilos carregada sob demanda falha.
- A documentação da API descreve as opções de módulos e os campos de configuração relacionados ao fnOS.

## Atualização

- Docker: baixe a nova imagem e recrie o contêiner. Binário: substitua o executável e reinicie.
- O aplicativo nativo para fnOS e a imagem Docker usam a porta 16680. Antes de trocar a imagem Docker pelo aplicativo nativo, pare o contêiner `gately` e copie o seu diretório de configuração para o `var/config` do aplicativo.
