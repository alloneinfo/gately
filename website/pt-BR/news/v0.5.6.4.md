# Gately v0.5.6.4 lançado

23 de outubro de 2026

Esta é uma atualização de recursos da série v0.5.6, baseada na sugestão da [issue #13](https://github.com/wangwanjie/gately/issues/13), que melhora a forma como os certificados chegam a outros serviços.

[Baixar v0.5.6.4](/pt-BR/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.4)

## Cópia para vários diretórios locais

A "Implantação automática" de um certificado ganhou "Copiar para diretório local". Adicione quantos diretórios precisar, cada um com seu próprio comando "Executar após copiar", por exemplo um para o nginx com `nginx -s reload` e outro para o ocserv com `systemctl reload ocserv`. Depois que o certificado é emitido, renovado ou atualizado, a cópia e os comandos são executados automaticamente; falhas são repetidas a cada hora e enviam a notificação "Certificado: falha na implantação". Se os arquivos de um diretório forem apagados ou alterados, a próxima verificação os copia de novo.

## Nomes de arquivo personalizados

"Copiar para diretório local" e "Enviar para host SSH" aceitam nomes de arquivo para o certificado (cadeia completa) e a chave privada, como `fullchain.pem` e `privkey.pem`. Com ambos preenchidos, apenas esses dois arquivos são gravados, sem precisar renomear no comando. Vazios, são usados os habituais `<observação>.crt`, `.pem` e `.key`. `$certFile` e `$keyFile` no comando apontam para os arquivos realmente gravados.

## Notas de atualização

- O "Mapeamento de certificados" existente não muda e continua funcionando; adicione diretórios em "Implantação automática" quando precisar de mais de um.
- Destinos SSH e Docker existentes não são implantados de novo após a atualização.
- Quando o Gately roda no Docker, os diretórios locais e os comandos ficam dentro do contêiner; monte nele os diretórios de destino.
