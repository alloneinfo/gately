# Gately v0.5.8 lançado

25 de outubro de 2026

Esta versão permite que o Gately atue como provedor de identidade OIDC, adiciona compartilhamento de arquivos via SMB ([#15](https://github.com/wangwanjie/gately/issues/15)), adiciona filtros a todos os logs ([#16](https://github.com/wangwanjie/gately/issues/16)) e permite mudar a ordem dos grupos de regras do WAF ([#17](https://github.com/wangwanjie/gately/issues/17)).

[Baixar v0.5.8](/pt-BR/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.8) · [Documentação do login único OIDC](/pt-BR/docs/modules/oidc)

## Login único OIDC

O Serviço Web inclui um provedor de identidade OpenID Connect. Gitea, OpenList, Grafana e outros aplicativos com suporte a login OIDC podem fazer login diretamente com os usuários compartilhados e saber quem entrou, substituindo a função OIDC do Authelia.

- Basta informar a URL do emissor e adicionar clientes em "Serviço Web → Configurações globais → Provedor de identidade OIDC"; o domínio do emissor não precisa de um site;
- Os usuários compartilhados ganham e-mail, nome de exibição e grupos opcionais, enviados aos aplicativos como as claims `email`, `name` e `groups`, para que os aplicativos criem contas automaticamente e concedam permissões de administrador por grupo;
- Cada cliente pode ser restrito a certos usuários ou grupos; há suporte a PKCE, tokens de atualização e `prompt=none` / `prompt=login`, e clientes públicos (aplicativos de página única, apps de celular) precisam usar PKCE;
- O login reaproveita a página de login da autenticação web e a verificação em dois fatores TOTP; quando o emissor fica dentro do domínio de SSO, quem já entrou em qualquer site acessa os aplicativos sem fazer login de novo;
- Trocar a senha ou o TOTP, excluir o usuário ou removê-lo da lista de permitidos invalida na hora os tokens já emitidos; `sub` é o ID fixo do usuário compartilhado e continua o mesmo após uma renomeação;
- A documentação traz exemplos de configuração para Gitea, OpenList e Grafana, todos verificados com os aplicativos reais.

## Serviço SMB

Os Serviços de arquivos ganham o Serviço SMB, que compartilha diretórios locais com o Explorador de Arquivos do Windows, o Finder do macOS, o Linux e clientes SMB em celulares e TVs:

- SMB 2.0.2 a 3.1.1, autenticação e assinatura NTLMv2, com criptografia SMB 3 obrigatória opcional;
- Os usuários são configurados como no FTP e no WebDAV; cada usuário só vê os próprios compartilhamentos, e cada diretório pode ser somente leitura;
- A página lista o endereço de conexão de cada compartilhamento, e o anúncio via Bonjour permite que o Finder descubra o serviço diretamente;
- Disponível apenas no Linux e no macOS. O Windows só se conecta à porta 445, então, se o Samba que vem com o NAS já a ocupa, escolha outra porta.

## Filtragem de logs

Logs do sistema e o cartão de logs de cada módulo podem ser filtrados por nível, origem, palavra-chave (com frases e palavras excluídas), IP ou faixa do cliente e intervalo de tempo; o Serviço Web também filtra por site, domínio e código de status. A filtragem acontece no servidor, e "Carregar logs anteriores" continua buscando nos arquivos de log gravados em disco. Os logs de acesso do Serviço Web e os logs de ocorrências do WAF registram o IP do cliente, o domínio, o código de status e o ID da regra; clicar em uma etiqueta de uma entrada filtra por esse valor. A API de logs aceita os mesmos parâmetros de filtro.

## Serviço Web e WAF

- Os cabeçalhos de requisição e de resposta dos sites são editados linha a linha, com nomes e valores escolhidos entre entradas comuns (HSTS, CSP, X-Frame-Options e outros); um clique adiciona os cabeçalhos de segurança comuns, e o formato e os erros frequentes são verificados enquanto você digita; o Content-Type dos sites de texto fixo pode ser escolhido entre os tipos comuns;
- Cabeçalhos de requisição cujo nome ou valor contém caracteres inválidos são rejeitados ao salvar; antes, uma configuração assim fazia o site inteiro retornar 502;
- Ao lado das Opções do proxy reverso há uma nova explicação do que cada uma das seis opções faz e de quando usá-la;
- Os grupos de regras do WAF podem ser movidos para cima e para baixo. Regras de permissão (`allow`, `ctl:` e semelhantes) ficam acima do OWASP CRS, e diretivas de remoção como `SecRuleRemoveById` ficam abaixo do CRS; a interface e a documentação explicam isso.

## Correções

- Renomear um usuário de FTP ou WebDAV sem digitar a senha de novo fazia o salvamento falhar.

## Notas de atualização

- Como atualizar: instalações por binário Linux atualizam pela página Sobre; no Docker, baixe a nova imagem e recrie o contêiner; no fnOS, instale o novo `.fpk` pela central de aplicativos; no OpenWrt, instale o novo `.ipk` / `.apk`.
- O formato da configuração é compatível com versões anteriores, então você pode atualizar diretamente. Os usuários compartilhados recebem um ID fixo na primeira inicialização, que é gravado de volta no arquivo de configuração.
- O formulário de login da autenticação web rejeita envios vindos de outros sites; o login normal continua funcionando.
