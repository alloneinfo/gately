# Gately v0.5.5.2 lançado

22 de outubro de 2026

Esta é uma versão de correção de segurança. Usuários do fnOS devem atualizar logo.

[Baixar v0.5.5.2](/pt-BR/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.5.2)

## Permissões de arquivos no diretório de configuração

Alguns sistemas de arquivos ignoram as permissões que um programa pede ao criar um arquivo. Por exemplo, os volumes do fnOS montados com `trimacl` criam todo arquivo e diretório novo como `0755`. Nesses volumes, outros usuários locais conseguiam ler o seguinte conteúdo criado pelo Gately:

- Os logs de execução (`logs/`) e o log de auditoria (`audit.log`), com IPs de clientes e domínios;
- O histórico de configuração (`history/`), com versões anteriores de regras e credenciais;
- As configurações geradas pelo módulo frp (`frp/`), com o token do frp;
- Os caches das listas de IP assinadas, os backups locais, os backups salvos automaticamente antes de uma restauração e o diretório de estado do Tailscale.

Os arquivos de configuração dos módulos (`*.json`) sempre foram salvos como `0600` e não foram afetados. Sistemas de arquivos comuns como ext4 também não.

Esta versão define as permissões explicitamente depois de criar arquivos e diretórios e, na inicialização, restringe o conteúdo existente desses tipos no diretório de configuração a `0600` para arquivos e `0700` para diretórios, registrando no log do sistema quantos itens mudou. Os programas que você colocou em `bin/` e o próprio diretório de configuração não são alterados.

## Notas de atualização

- A partir da v0.5.5, instalações por binário Linux atualizam pela página Sobre; no Docker, baixe a nova imagem e recrie o contêiner; no fnOS, instale o novo `.fpk` pela central de aplicativos; no OpenWrt, instale o novo `.ipk` / `.apk`.
- "Verificar atualizações" na v0.5.4 e anteriores não entende números de versão de quatro partes. Use "Enviar pacote de atualização" na página Sobre ou atualize primeiro para a v0.5.5.
- Se você copiou arquivos do diretório de configuração para outro lugar (por exemplo, um compartilhamento do NAS como backup), verifique você mesmo as permissões dessas cópias.
