# Gately v0.5.9.1 publicado

26 de octubre de 2026

Es una actualización de la serie v0.5.9, basada en la sugerencia de [issue #25](https://github.com/wangwanjie/gately/issues/25), que además corrige dos editores que no podían guardar.

[Descargar v0.5.9.1](/es/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9.1)

## HTTP y HTTPS en el mismo puerto

Los listeners con HTTPS tienen la opción «HTTP en el mismo puerto», en «Rechazar» por defecto. Con «Redirigir a HTTPS», `http://host:puerto` redirige a `https://host:puerto` (301 para GET y HEAD, 308 para los demás métodos, que conserva el método y el cuerpo); con «Servir», los sitios se responden por HTTP sin cifrar. Resulta útil cuando solo se puede mapear un puerto y los visitantes pueden equivocarse de esquema, como en un puerto no estándar de una conexión doméstica.

Gately distingue TLS de HTTP por el primer byte de cada conexión. Las cabeceras del protocolo PROXY se siguen leyendo antes, la negociación HTTP/2 y los desafíos ACME HTTP-01 siguen funcionando y `Alt-Svc` solo se envía por HTTPS. Al importar configuraciones de nginx, `error_page 497 https://$host:$server_port$request_uri` en un server HTTPS pasa a «Redirigir a HTTPS». Consulte [Servicio web](/es/docs/modules/web).

## URL de acceso de File Browser

Una instancia de File Browser puede tener varias URL de acceso, como `https://files.example.com/` publicada mediante proxy inverso del Servicio web. La tarjeta de la instancia las muestra y, si la lista está vacía, la dirección se sigue deduciendo de la dirección y el puerto de escucha. El esquema, el host y el puerto de la primera URL se usan como URL externa de File Browser, que emplean los enlaces compartidos. Consulte [Servicios de archivos](/es/docs/modules/tools#filebrowser).

## Correcciones

- Guardar una instancia de File Browser editada fallaba con `json: unknown field "state"`. Corregido.
- Guardar un túnel de Cloudflare editado fallaba con el mismo error `json: unknown field "state"`. Corregido.
- Con los usuarios compartidos activados, los registros de escucha de FTP y WebDAV mostraban 0 usuarios ([issue #26](https://github.com/wangwanjie/gately/issues/26)). Ahora indican «N usuarios, M de ellos compartidos» como SMB, y WebDAV registra los nuevos totales cuando cambian los usuarios compartidos.

## Notas de actualización

- «HTTP en el mismo puerto» está desactivado por defecto, así que los listeners existentes se comportan igual. Cambiarlo reinicia el listener y cierra sus conexiones abiertas.
- Con «Servir», los sitios a los que se accede por HTTP no van cifrados y las contraseñas de la autenticación web y de los usuarios compartidos también viajan en claro. Para el acceso desde internet use «Redirigir a HTTPS».
