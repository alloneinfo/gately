# セキュリティモデルとプライバシーの約束

Gately はネットワーク境界で動作し、DNS プロバイダーのキー、証明書の秘密鍵、各種認証情報を扱います。そのため、セキュリティと透明性を最優先の設計目標としています。

## プライバシーの約束

- **デフォルトで外部接続ゼロ**：プロジェクト側のサーバーには一切接続せず、端末情報も送信せず、リモートからの設定配信も行いません。
- **外部アドレスを確認・変更可能**：公開 IP の照会先や STUN サーバーなどのアドレスはすべて画面に表示され、変更や無効化ができます。
- **外部ログインは自己管理**：GitHub、Google、QQ、OIDC のログインには自分で取得した OAuth アプリを使い、中継サービスは一切経由しません。
- **アップグレードは自分の判断で**：プログラムがバックグラウンドで自身のバイナリを置き換えることはなく、アップグレードのタイミングはあなたが決めます。

## データ保護

- 設定は平文の JSON でパーミッションは 0600。監査とロールバックができます。
- 機密フィールドは API 出力でマスクされます。
- cloudflared のトークンは環境変数で渡されるためプロセス一覧に現れません。frp と Tailscale のトークンやキーはパーミッション 0600 で保存されます。

## 認証とアクセス制御

- bcrypt によるパスワードハッシュと、HMAC 署名付きのセッショントークン
- 2 段階認証（TOTP。RFC 6238 のテストベクターで検証済み）
- ログイン失敗のレート制限
- セキュアエントリー、LAN 内からのみ許可、管理画面の HTTPS
- 複数トークンの API：各トークンには作成時に選択したモジュールの読み書き権限のみが付与され、有効期限を設定でき、最後に使われた接続元 IP が記録されます。アカウント、2 段階認証、トークン管理、さらにバックアップ、復元、再起動、システム設定のエンドポイントはログインセッションからのみ利用できます。詳しくは [API トークンと OpenAPI](/ja/docs/reference/api) を参照してください
- サイトのアクセス制御：認証失敗時の自動ブロック、GeoIP による国フィルター、パスルール。詳しくは [Web サービス](/ja/docs/modules/web) を参照してください
- 設定バックアップは暗号化（scrypt + AES-GCM）に対応しています。詳しくは [設定バックアップ](/ja/docs/modules/backup) を参照してください

## 高リスク機能のデフォルト値

ローカルシェルのターミナルはデフォルトで無効です。SSH ターミナルは「初回信頼（Trust On First Use）」方式でホスト鍵のフィンガープリントを記録します。

## セキュリティ問題の報告

脆弱性は GitHub リポジトリの Security ページから非公開で報告し、公開 Issue に詳細を書かないでください：<https://github.com/wangwanjie/gately/security>

その他の実践的な推奨事項は [ハードニングの推奨事項](/ja/docs/guide/hardening) を参照してください。
