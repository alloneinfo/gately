# よくある質問

## プロジェクト側のサーバーへの接続は必要ですか？

接続は不要です。Gately はデフォルトでプロジェクト側のサーバーに接続せず、端末情報も送信しません。公開 IP の照会などの外部アドレスにはサードパーティの公開サービスが使われ、対応するタスクで変更できます。

## 初期パスワードはどこで確認できますか？

初回起動時にログへ出力されます（1 度だけ表示されます）。Docker でデプロイしている場合は `docker logs gately 2>&1 | grep -i "initial password"` を実行してください。

## 管理者パスワードを忘れた場合は？

Gately を停止し、設定ディレクトリの `account.json` を削除してから起動し直してください。プログラムが `admin` アカウントを再作成し、新しい初期パスワードをログに出力します。ログイン後は、2 段階認証などのセキュリティ設定を確認してください。

## なぜ `--network host` を推奨しているのですか？

ポート転送、STUN、Web サービスは、ホストのポートを直接待ち受ける必要があります。ブリッジネットワークを使う場合は、使用するポートを 1 つずつ自分でマッピングしてください。

## Lucky と同時に動かせますか？

動かせます。管理ポートのデフォルトは 16680 で、Lucky の 16601 とは競合しません。インポートしたルールはデフォルトで無効になるため、稼働中の Lucky とポートやルーターの UPnP マッピングを取り合うこともありません。

## Tailscale、frp、cloudflared のバイナリを自分で配置する必要があるのはなぜですか？

この 3 つのモジュールは公式の外部プログラムを管理します。Gately 本体には内蔵していないため、常に上流の最新バージョンを使えます。配置場所は [設定と起動オプション](/ja/docs/guide/configuration) を参照してください。

## STUN ルールを有効にしても外部からアクセスできません

ルーターの WAN 側がキャリアグレード NAT（100.64.0.0/10）の配下にある場合、外部から穿孔したポートにアクセスできません。これはネットワーク環境自体の制約です。[Tailscale / frp / Cloudflare トンネル](/ja/docs/modules/tunnels) への切り替えを検討してください。

## 問題の報告や開発への参加はどうすればよいですか？

[GitHub Issues](https://github.com/wangwanjie/gately/issues) で報告してください。開発の決まりごとは [コントリビュート](/ja/docs/guide/contributing) を参照してください。
