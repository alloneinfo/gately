# 監査ログと設定履歴

Gately は DNS のキーや証明書の秘密鍵を扱うため、いつ誰が何をしたか、設定がどう変わったかを追跡し、元に戻せるようにしておく必要があります。

## 監査ログ

サイドバーの「システム → 監査ログ」には、以下の操作が新しい順に表示されます。種別で絞り込んだり、パス・ユーザー・IP で検索したりできます。

| 種別 | 記録内容 |
| --- | --- |
| ログイン | パスワード、Passkey、外部サービスによるログインの成功と失敗、およびログアウト |
| 変更 | 管理画面と API トークンから行われたすべての書き込み操作（追加、変更、削除、有効化・無効化、ロールバックなど） |
| 機密アクセス | 設定バックアップ・診断パッケージ・証明書の秘密鍵のダウンロード、Web ターミナルやコンテナターミナルの起動など |

各記録には日時、操作者（ユーザー名または `api-token:<トークン名>`）、接続元 IP、メソッド、パス、ステータスコードが含まれます。**リクエスト本文やシークレットは一切記録しません**。

- ログは設定ディレクトリの `audit.log`（JSON Lines）に書き込まれます。1 ファイルが 5 MiB を超えるとローテーションし、過去分を 3 つ保持します
- 管理画面を同じホスト上のリバースプロキシの背後に置いた場合も、実際の接続元が記録され、経由したプロキシのアドレスは別に記録されます。仕組みは [セキュリティモデル](/ja/docs/guide/security) を参照してください
- 変更と機密アクセスは `audit.change`、`audit.access` イベントとして発行されます。[通知センター](/ja/docs/modules/notify) で「設定変更」「セキュリティとログイン」テンプレートを使って通知できます
- 読み取り専用アカウントと API トークンでは監査ログを閲覧できません

## 設定履歴とロールバック

設定ファイルを上書きする前に、Gately は古い内容を履歴バージョンとして設定ディレクトリの `history/<名前>/` に保存します。設定ごとに直近 30 個を保持します。`account.json`（アカウントの認証情報）と `tokens.json`（トークン）は履歴を残しません。

「システム → 設定履歴」では次の操作ができます。

1. 設定ファイルを選び、各バージョンの保存日時とサイズを確認します
2. 「比較」をクリックすると、そのバージョンと現在の設定の行単位の差分を確認できます
3. 「ロールバック」をクリックするとそのバージョンに戻り、反映のため Gately が自動的に再起動します

ロールバック前の現在の内容も新しい履歴バージョンとして保存されるため、ロールバック自体も元に戻せます。
