# Tailscale / frp / cloudflared

3 つのモジュールは、公式プログラムをプロセス管理方式で統合しています。自動再起動、ログの画面への集約、設定は画面上で完結します。Gately 本体にはこれらのプログラムを内蔵していないため、常に上流の最新バージョンを使えます。

## プログラムの配置

実行ファイルは次の順序で探されます。

1. モジュール設定に入力したパス
2. `PATH`
3. 設定ディレクトリ配下の `bin/` サブディレクトリ

Docker でデプロイする場合は、マウントした設定ディレクトリにバイナリを置くだけで使えます（例：`./gately-data/bin/frpc`）。Tailscale には `tailscale` と `tailscaled` の両方が必要です。

トークンとキーはパーミッション 0600 で保存されます。cloudflared のトークンは環境変数で渡されるため、プロセス一覧には現れません。

## Tailscale

- `tailscaled` を管理する（ユーザースペースネットワーク、コンテナ向き）か、システムに既にあるデーモンに接続します
- 認証キーまたはログインリンク。Headscale にも対応
- サブネットルーターとエグジットノード
- ノード一覧と SOCKS5 プロキシ
- WireGuard の UDP ポートを固定でき、ファイアウォールで直接接続を許可しやすくなります
- tailscaled の追加パラメーターと環境変数。ホストの iptables が nf_tables バックエンドの場合は、環境変数に `TS_DEBUG_FIREWALL_MODE=nftables` を追加すると、サブネット転送が有効になります

## frp

- **frpc クライアント**：tcp / udp / http / https / stcp / xtcp のプロキシ。追加・削除はすぐに反映されます
- **frps サーバー**：ポートのホワイトリスト、サブドメイン、ダッシュボード
- **既存設定のインポート**：ページ上部の「設定をインポート」は、旧バージョンの `frpc.ini` / `frps.ini`（`[common]` セクションを含む）と frp 0.52+ の `toml` に対応しており、ファイルの選択または内容の貼り付けができます。まず解析結果と無視されたフィールドをプレビューしてから、インポートを確定します。クライアントでは、追記（同名のプロキシは変更されません）またはすべてのプロキシの置き換えを選べます。インポートで有効状態は変わりません。API の `POST /api/frp/import` からも呼び出せます。
- **Lucky からの移行**：`lucky_frp.lkcf` の最初のクライアントインスタンスと最初のサーバーインスタンスをそのままインポートできます。[Lucky からの移行](/ja/docs/guide/migration) を参照してください。

## Cloudflare トンネル

- トークン方式のトンネルと trycloudflare の一時トンネル
- 複数トンネルと自動再起動
- 公開アドレスの表示
- トンネルトークンを使うトンネルは Lucky からインポートできます

## 選び方

| シナリオ | おすすめ |
| --- | --- |
| 複数のデバイス間でプライベートネットワークを構成する | Tailscale |
| 自分の公開サーバーがあり、LAN 内のサービスをそこへマッピングする | frp |
| 公開 IP もサーバーもなく、手早く Web サービスを公開する | Cloudflare トンネル |
| 回線事業者の NAT でホールパンチングが可能 | [STUN 穿孔](/ja/docs/modules/stun) |
