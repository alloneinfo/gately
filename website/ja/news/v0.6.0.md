# Gately v0.6.0 リリース

2026年10月27日

このリリースでは frp を複数インスタンスで実行できるようにし、Web サービスにユーザーごとの振り分け（[#29](https://github.com/wangwanjie/gately/issues/29)）、サイトのグループ化と並べ替え（[#28](https://github.com/wangwanjie/gately/issues/28)）、サインイン Cookie の転送（[#30](https://github.com/wangwanjie/gately/issues/30)）を追加しました。別の DNS プロバイダーでホストしているサブドメインの証明書発行も修正しています（[#27](https://github.com/wangwanjie/gately/issues/27)）。

[v0.6.0 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.6.0)

## frp の複数インスタンス

- 複数の frpc インスタンス（それぞれ 1 台の frps に接続）と複数の frps インスタンス（それぞれ独自のポートで待ち受け）を同時に実行できます。各インスタンスは独立したプロセスで、専用の設定ファイルとログソースを持ち、個別に起動・停止、再起動、編集、削除できます。
- プロキシはいずれかの frpc インスタンスに属し、一覧はインスタンスで絞り込めます。プロキシを変更すると設定が変わったインスタンスだけが再起動されます。frpc インスタンスを削除するとそのプロキシも削除されます。
- プログラムのパスは独立した「プログラム」カードに移動しました。
- ini / toml 設定のインポート先として既存のインスタンスか新しいインスタンスを選べます。Lucky からのインポートではすべての frpc / frps インスタンスを取り込みます。
- 旧バージョンの単一の frpc / frps 設定は、アップグレード時に frpc / frps という名前のインスタンスへ自動移行され、トークンとプロキシはそのまま引き継がれます。

詳しくは [ネットワーク接続と NAT 越え](/ja/docs/modules/tunnels) を参照してください。

## Web サービス

- **サインインユーザーごとの振り分け**：Basic 認証、Web 認証、転送認証を有効にしたリバースプロキシサイトでは、指定したユーザーをそれぞれのバックエンドに送れます。nginx の `map $remote_user $backend` と同様の機能です。ユーザーにはサイトユーザー、共有ユーザー、サードパーティサインインの `プロバイダー:ID`、転送認証が返す `Remote-User` を指定できます。一覧にないユーザーと、公開パスでサインインしていない訪問者はサイトのバックエンドを使います。`X-Remote-User` のようなヘッダーでユーザー名をバックエンドに渡すこともでき、訪問者が送った同名のヘッダー（ハイフンの代わりにアンダースコアを使った表記を含む）は常に削除されます。
- **サイトのグループ化・並べ替え・検索**：サイトにグループを設定でき、一覧はリスナーごとに折りたためるグループで表示されます。「並べ替え」モードではサイトを上下に移動したりドラッグしたりでき、グループごとの移動やリスナーの並べ替えもできます。ヘッダーの検索ボックスでドメイン、名前、グループ、バックエンド、備考を対象に絞り込めます。順序は一覧の表示だけに影響し、ドメインの照合には関係しません。
- **Gately サインイン Cookie の転送**：リバースプロキシサイトの新しいオプションです。有効にすると、シングルサインオンとサイトセッションの Cookie がそのままバックエンドに転送されます。これにより、公開側の Gately は WAF とアクセス制御だけを担い、LAN 内の Gately が Web 認証とシングルサインオンを担当する構成が取れます。同じサイトの認証とは同時に有効にできません。

詳しくは [Web サービス](/ja/docs/modules/web) を参照してください。

## 証明書

ゾーンを空欄にした場合、DNS-01 検証ではまず SOA クエリで検証レコードの権威ゾーンを調べます。別の DNS プロバイダーでホストしているサブドメイン（web.example.com を example.com とは別にホストする場合など）や多段のサフィックスも正しく検出されます。検索に失敗した場合や、見つかったゾーンが登録可能ドメインより短い場合（ローカル DNS が上位ドメインを上書きしている場合など）は、ドメイン名からゾーンを推定し、その理由をログに記録します。証明書ごとに設定した DNS サーバーは、その証明書にだけ使われるようになりました。

## 保存済みのパスワードを表示

マスクされたパスワード、トークン、鍵の横に目のボタンが付き、クリックすると新しい `.../secrets` エンドポイントから平文を取得します：

- 書き込み権限が必要です。読み取り専用アカウントと読み取り専用 API トークンには 403 が返り、表示のたびに監査ログに記録されます。
- Web ターミナルの接続と認証プリセットのパスワードは、ターミナルを開くときと同じく、先にターミナルの二段階認証を通過する必要があります。
- bcrypt で保存された Web ユーザーのパスワード、OIDC クライアントシークレット、秘密鍵は返されません。
- 二段階認証を有効にした共有ユーザーは QR コードを再表示できます。
- `gately mcp` の既定の読み取り専用モードではこれらのエンドポイントは提供されず、`--write` を付けると提供されます。

## アップグレードについて

- アップグレード方法：Linux バイナリ版は「バージョン情報」ページから直接アップグレードできます。Docker は新しいイメージを取得してコンテナを再作成、fnOS はアプリセンターで新しい `.fpk` を、OpenWrt は新しい `.ipk` / `.apk` をインストールします。
- 設定ファイルの形式は後方互換のため、そのままアップグレードできます。frp の旧設定は初回起動時にインスタンスへ移行され、旧バージョンが生成した `frp/frpc.toml` と `frp/frps.toml` は削除されます。
- `/api/frp/client` と `/api/frp/server` エンドポイントは削除され、`/api/frp/clients`、`/api/frp/servers`、`/api/frp/settings` に置き換わりました。旧エンドポイントを呼び出しているスクリプトは修正が必要です。
- Docker レジストリのパスワードのマスクは他のモジュールと同じ 8 個のアスタリスクになりました。旧来の 6 個のアスタリスクも引き続き認識されます。
