# Gately v0.5.9 リリース

2026年10月26日

このリリースでは File Browser のホスト（[#23](https://github.com/wangwanjie/gately/issues/23)）と IP アドレス証明書（[#24](https://github.com/wangwanjie/gately/issues/24)）を追加し、ホストしている外部プログラムをすべてオンラインでインストール・ロールバックできるようにしました。

[v0.5.9 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9)

## File Browser

「ファイルサービス」に「File Browser」を追加し、Web ファイルマネージャー [FileBrowser Quantum](https://github.com/gtsteffaniak/filebrowser) をホストします。本家の filebrowser/filebrowser は 2026 年にアーカイブされ、セキュリティ修正が提供されなくなったため、メンテナンスが続いている Quantum フォークを採用しました。

- インスタンスごとに待ち受けアドレスとポート、ベースパス（パス単位のリバースプロキシ向け）、1 つ以上の共有ディレクトリ（それぞれ読み取り専用にできます）、画面の言語、ログインの有効期間を設定できます；
- ログイン方法はユーザー名とパスワード、リバースプロキシから渡されるユーザー名ヘッダーの信頼（Web サービスの Web 認証と組み合わせて使用）、ログインなし（目立つ警告を表示）から選べます；
- 管理者パスワードは環境変数で File Browser に渡し、起動のたびに同期します。ファイルには一切書き込みません；
- 共有ディレクトリが存在しない場合は起動を拒否します。インスタンスを削除するとそのデータディレクトリ（ユーザー、共有リンク、キャッシュ）も削除しますが、共有ディレクトリ内のファイルには影響しません。

詳しくは [ファイルサービス](/ja/docs/modules/tools) を参照してください。

## IP アドレス証明書と短期証明書

ACME 証明書に「証明書プロファイル」を追加しました。CA のデフォルト、Let's Encrypt の短期証明書（約 6 日）、または CA が対応するその他のプロファイル名を選べます。

- ドメイン一覧にグローバル IPv4・IPv6 アドレスを直接入力して、IP アドレス証明書を発行できます。IP 証明書には HTTP-01 検証が必要で、Let's Encrypt では短期証明書を選ぶ必要があります。エディターがその旨を表示し、ワンクリックで設定できます；
- プリセットの CA はグローバルアドレスにのみ発行するため、プライベート、ループバック、100.64.0.0/10 のアドレスは拒否されます。自前の CA（step-ca など）にはこうした制限はありませんが、HTTP-01 検証は必要です；
- SNI のない TLS 接続（IP でのアクセス）には、ローカルアドレスに一致する IP 証明書が自動で使われます；
- 短期証明書は「短期証明書の更新タイミング（時間前）」に従って期限前に更新され（デフォルト 24 時間、最大 80 時間）、失敗した場合は 1 時間ごとに再試行します。証明書カードには「短期」タグと残り時間が表示されます。

詳しくは [SSL 証明書](/ja/docs/modules/ssl) を参照してください。

## ホストするプログラムのオンラインインストール

frp、cloudflared、Tailscale、File Browser の各ページに「オンラインインストール」カードを追加しました：

- 最新の正式版または指定したバージョン（ダウングレードも可）をインストールできます。ダウンロード後に SHA-256 を検証し、このマシンで実行できることを確認してから置き換え、そのプログラムを使うプロセスを自動で再起動します；
- プログラムごとにダウンロードプロキシ（http、https、socks5）を設定できます。空欄の場合は全体の「更新用プロキシ」を使います；
- 置き換えた旧バージョンは設定ディレクトリの `bin/.versions/` に最大 3 つ保存され、ワンクリックでロールバックまたは削除できます；
- 「アンインストール」はインストールしたプログラムと旧バージョンをすべて削除し、モジュールの設定は残します；
- ページ上部の「デフォルト設定に戻す」はプロセスを停止してモジュールの設定をデフォルトに戻し、旧設定は設定履歴に保存されます；
- Tailscale のオンラインインストールは Linux のみです（macOS、Windows 向けの公式静的パッケージがないため）。

プログラムの検索順序は、ページで指定したパス → 設定ディレクトリの `bin/` → `PATH` の順に変わり、オンラインインストールしたプログラムが優先されます。詳しくは [ネットワーク接続と NAT 越え](/ja/docs/modules/tunnels) を参照してください。

## ファイルサービスの共有ユーザー

WebDAV、FTP、SMB の共有ユーザーは「ファイルサービス → ファイル共有ユーザー」の専用ページで編集するようになりました。このページには、各サービスが有効か、共有ユーザーを許可しているか、同名のローカルユーザーに上書きされている共有ユーザーはどれかが表示されます。各サービスのページには「共有ユーザーのログインを許可」スイッチだけが残ります。新しい API `GET/PUT /api/fileusers` とトークン権限 `fileusers:read`、`fileusers:write` を追加しました。従来の `/api/<サービス>/shared-users` も引き続き使えます。

## アップグレードについて

- アップグレード方法：Linux バイナリ版は「バージョン情報」ページから直接アップグレードできます。Docker は新しいイメージを取得してコンテナを再作成、fnOS はアプリセンターで新しい `.fpk` を、OpenWrt は新しい `.ipk` / `.apk` をインストールします。
- 設定ファイルの形式は後方互換のため、そのままアップグレードできます。既存の証明書がアップグレードによって再発行されることはありません。
- 検索順序の変更により、設定ディレクトリの `bin/` に同名のプログラムがある場合は、`PATH` にあるものより優先して使われます。
- 「機能モジュール」で無効にしたファイルサービスがあっても、共有ユーザーを変更できるようになりました。
