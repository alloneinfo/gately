# Gately v0.5.6.2 リリース

2026年10月23日

v0.5.6 系の修正リリースです。すべてのデプロイ方法でアップグレードをおすすめします。

[v0.5.6.2 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.2)

## Docker 29 で Docker モジュールが使えるように

Docker 25 から対応する最小 API バージョンが段階的に上がり、Docker 29 では 1.44 以上が必要です。Gately は 1.41 固定だったため、Docker 画面に接続できないと表示されていました。現在は初回接続時に対応範囲を読み取り、1.41 に対応していればそのまま、未対応ならデーモンの最小バージョン、20.10 より古いエンジンではそのエンジン自身のバージョンを使います。

## 未ログイン時は直接ログイン画面へ

セッションはページから読めない Cookie に保存されているため、未ログインで管理画面を開くと API が 401 を返すまで概要画面が表示されていました。現在はページ表示前にセッションを確認し、未ログインなら直接ログイン画面を表示し、ログイン後は元のページに戻ります。

## Lucky から移行した Cloudflare 設定に対応

Lucky の Cloudflare は API トークンのみを使い、移行した設定の ID 欄には他社の AccessKey が残っていることがよくあります。Gately はこれをアカウントのメールアドレスとみなして Global API Key 認証を使い、DDNS と証明書の検証が 6003 Invalid request headers で失敗していました。現在は ID がメールアドレスの場合のみ Global API Key を使い、それ以外は API トークンで認証します。

## 名前を変えた DDNS レコードをすぐ同期

タスクを編集した際、ドメイン・種類・回線・TTL を変えたレコードが変更前の同期状態を引き継ぎ、同期済みとみなされて新しいレコードが作成されませんでした。現在は保存後に再同期します。

## アップグレードについて

- Docker は新しいイメージを取得してコンテナを再作成してください。その他のデプロイ方法は「設定」からオンラインアップグレードするか、新しいパッケージを上書きインストールしてください。
- エラー 6003 のために手動で Cloudflare の ID を空にしたタスクは、元に戻す必要はありません。
