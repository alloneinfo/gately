# Gately v0.5.6.4 リリース

2026年10月23日

v0.5.6 系の機能アップデートです。[issue #13](https://github.com/wangwanjie/gately/issues/13) の提案をもとに、証明書を他のサービスへ配る方法を改善しました。

[v0.5.6.4 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.4)

## 複数のローカルディレクトリへコピー

証明書の「自動デプロイ」に「ローカルディレクトリへコピー」を追加しました。ディレクトリはいくつでも追加でき、それぞれに「コピー後に実行」するコマンドを設定できます。たとえば nginx 用のディレクトリでは `nginx -s reload`、ocserv 用では `systemctl reload ocserv` を実行できます。証明書の発行・更新後に自動でコピーしてコマンドを実行し、失敗時は 1 時間ごとに再試行して「証明書：デプロイ失敗」通知を送ります。ディレクトリ内の証明書ファイルが削除・変更された場合は、次回のチェックで再度コピーします。

## 証明書ファイル名の指定

「ローカルディレクトリへコピー」と「SSH ホストへアップロード」では、証明書（フルチェーン）と秘密鍵のファイル名を `fullchain.pem`、`privkey.pem` のように指定できます。両方入力するとこの 2 ファイルだけを書き込むため、コマンドで名前を変える必要はありません。空欄の場合は従来どおり `<備考>.crt`、`.pem`、`.key` になります。コマンド内の `$certFile`、`$keyFile` は実際に書き込んだファイルを指します。

## アップグレード時の注意

- 既存の「証明書マッピング」は変わらず使えます。複数のディレクトリが必要な場合は「自動デプロイ」に追加してください。
- 既存の SSH と Docker のデプロイ先は、アップグレード後に再デプロイされません。
- Gately を Docker で動かしている場合、ローカルディレクトリとコマンドはコンテナ内のものなので、対象ディレクトリをコンテナにマウントしてください。
