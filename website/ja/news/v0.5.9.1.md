# Gately v0.5.9.1 リリース

2026年10月26日

v0.5.9 系のアップデートです。[issue #25](https://github.com/wangwanjie/gately/issues/25) の提案をもとにし、編集後に保存できなかった 2 か所を修正しました。

[v0.5.9.1 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9.1)

## HTTP と HTTPS を同一ポートで

HTTPS を有効にしたリスナーに「同一ポートの HTTP」オプションを追加しました。既定値は「受け付けない」です。「HTTPS へリダイレクト」では `http://ホスト:ポート` を `https://ホスト:ポート` へリダイレクトし（GET と HEAD は 301、その他のメソッドはメソッドと本文を保つ 308）、「そのまま提供」では平文 HTTP でサイトを提供します。家庭回線の非標準ポートなど、ポートを 1 つしか割り当てられず、訪問者がスキームを打ち間違えても開けるようにしたい場合に便利です。

Gately は各接続の最初の 1 バイトで TLS と HTTP を判別します。PROXY プロトコルヘッダーはその前に読み取られ、HTTP/2 のネゴシエーションと ACME HTTP-01 チャレンジはそのまま動作し、`Alt-Svc` は HTTPS の応答でのみ送信します。nginx 設定のインポートでは、HTTPS の server 内の `error_page 497 https://$host:$server_port$request_uri` が「HTTPS へリダイレクト」に変換されます。詳しくは [Web サービス](/ja/docs/modules/web) を参照してください。

## File Browser のアクセス URL

File Browser インスタンスに、Web サービスでリバースプロキシした `https://files.example.com/` などのアクセス URL を複数設定できます。インスタンスカードにはそれらが表示され、空の場合は従来どおり待ち受けアドレスとポートから推測します。最初の URL のスキーム、ホスト、ポートは File Browser の外部 URL になり、共有リンクに使われます。詳しくは [ファイルサービス](/ja/docs/modules/tools#filebrowser) を参照してください。

## 修正

- 既存の File Browser インスタンスを編集して保存すると `json: unknown field "state"` になる問題を修正しました。
- 既存の Cloudflare トンネルを編集して保存すると同じく `json: unknown field "state"` になる問題を修正しました。
- 共有ユーザーを有効にすると、FTP と WebDAV の待ち受けログでユーザー数が 0 と表示されていました（[issue #26](https://github.com/wangwanjie/gately/issues/26)）。SMB と同様に「N 人のユーザー（うち共有ユーザー M 人）」と表示するようになり、WebDAV は共有ユーザーが変わると新しい人数を記録します。

## アップグレード時の注意

- 「同一ポートの HTTP」は既定でオフのため、既存のリスナーの動作は変わりません。変更するとそのリスナーが再起動し、確立済みの接続は切断されます。
- 「そのまま提供」では平文 HTTP でアクセスしたサイトは暗号化されず、Web 認証や共有ユーザーのパスワードも平文で送られます。インターネットからのアクセスには「HTTPS へリダイレクト」をおすすめします。
