# Gately v0.5.4 リリース

2026年10月21日

今回のリリースはインストールとアップグレードに関するものです。Linux バイナリ導入（systemd、PVE の LXC コンテナ、手動で導入した OpenWrt など）は管理画面から直接アップグレードできるようになり、OpenWrt と iStoreOS のユーザーはシステムのパッケージマネージャーで Gately をインストールできます。

[v0.5.4 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.4)

## オンラインアップグレード

「バージョン情報」ページで「アップデートを確認」をクリックすると、新しいバージョン、リリース日、更新内容がダイアログに表示されます。「今すぐアップグレード」をクリックすると、Gately は次の順に処理します。

1. このプラットフォーム用のリリースパッケージを GitHub からダウンロードします。
2. 同じリリースの `checksums.txt` と SHA-256 を照合します。
3. 新しいバイナリを試験実行し、このマシンで動くことを確認します。
4. 実行ファイルを置き換えてその場で再起動します。旧バージョンは同じディレクトリに `gately.old` として残るため、ロールバックできます。

ダイアログには現在のステップ、ダウンロードの進捗と速度が表示され、バイナリを置き換える前ならいつでも取り消せます。ページを再読み込みしても実行中のアップグレードの表示が再開され、失敗した場合は理由と再試行ボタンが表示されます。

- **PVE の LXC コンテナ**：OCI イメージから作成した LXC コンテナもオンラインでアップグレードでき、削除して作り直す必要はありません。
- **更新用プロキシ**：GitHub への接続が不安定な場合は、「バージョン情報」ページまたは「設定 → ネットワークと実行」で http、https、socks5 のプロキシを設定できます。更新確認とダウンロードの両方がこのプロキシを経由します。
- **オフラインでのアップグレードとロールバック**：「アップグレードパッケージをアップロード」は任意のバージョンのリリース tar.gz または展開済みのバイナリを受け付けるため、ロールバックにも使えます。
- **管理者の操作でのみ実行**：Gately が自動でバージョンをダウンロードしたりインストールしたりすることはありません。Docker、fnOS、OpenWrt パッケージでのインストールでは、それぞれのアップグレード方法が案内されます。

[インストールとデプロイ · オンラインアップグレード](/ja/docs/guide/install#online-upgrade) を参照してください。

## OpenWrt パッケージ

各リリースに amd64 / arm64 / arm / mipsle / mips / riscv64 向けの OpenWrt パッケージが含まれるようになりました。

- OpenWrt 24.10 以前（iStoreOS を含む）：`opkg install ./gately_v0.5.4_openwrt_<arch>.ipk`
- OpenWrt 25.12 以降：`apk add --allow-untrusted ./gately_v0.5.4_openwrt_<arch>.apk`

インストール後に自動起動が有効になり、サービスがすぐに起動します。管理画面は `http://<ルーターのアドレス>:16680` です。設定は `/etc/gately` に保存され、アップグレード、アンインストール、ファームウェアの更新をしても保持されます。アップグレードは新しいパッケージをインストールするだけです。インストール前にデバイスのアーキテクチャを確認するため、`/etc/openwrt_release` の `DISTRIB_ARCH` に合わせてパッケージを選んでください。バイナリは約 35 MB で、x86 のソフトルーターや ARM64 ボックスなどストレージに余裕のあるデバイスに向いています。

[インストールとデプロイ · OpenWrt](/ja/docs/guide/install#openwrt) を参照してください。

## 修正

- Gately 自身を経由して管理画面にアクセスしている場合でも、設定を保存したときに接続が切れなくなりました。ポート転送ルールを編集したとき、待ち受けポート、プロトコル、モード、制限が変わらなければ、転送先と SNI ルートをその場で入れ替えて既存の接続を維持します。ポート転送や Web サービスの設定を保存しても、すべてのリスナーを再起動することはなくなりました。
- WAF が `credentials` や `forwardAuth` などの JSON フィールド名を OS のファイルアクセスと誤判定しなくなりました。以前は DDNS タスクの保存や Web サービスのリスナー追加で 403 が返されていました。
- ドメイン、IP リスト、ヘッダー、STUN サーバーなどのリスト入力欄が、入力中の Enter、カンマ、スペースを取り込んでしまう問題を修正しました。
- mips / mipsle のバイナリをソフトウェア浮動小数点でビルドするようにし、ハードウェア FPU のないルーターでも動作するようになりました。
- バージョン比較を semver に従うようにし、新しいビルドに古いバージョンへの「アップグレード」が提示されなくなりました。

## アップグレード

- オンラインアップグレードは v0.5.4 から使えるため、今回のアップグレードはまだ手動です。バイナリを置き換えて再起動する、新しい Docker イメージを取得してコンテナを再作成する、または fnOS のアプリセンターで新しい `.fpk` をインストールしてください。次回以降は「バージョン情報」ページからアップグレードできます。
- OpenWrt に Gately を手動で導入している場合は、その上から `.ipk` / `.apk` をインストールできます。`/etc/gately` の設定はそのまま使えます。
