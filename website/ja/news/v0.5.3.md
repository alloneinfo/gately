# Gately v0.5.3 リリース

2026年10月21日

今回のリリースの中心は fnOS です。Gately を fnOS のネイティブアプリとしてインストールできるようになりました。fnOS デスクトップのアイコンから開き、普段 fnOS に使っているアクセス入口をそのまま使えます。fnOS 管理者は改めてログインする必要がありません。また、使わない機能モジュールを丸ごと無効にできます。

[v0.5.3 をダウンロード](/ja/download#fnos) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.3)

## fnOS ネイティブアプリ

各リリースには fnOS 向けのオフラインパッケージ `gately_0.5.3_fnos_x86.fpk`（Intel / AMD）と `gately_0.5.3_fnos_arm.fpk`（ARM）が含まれます。fnOS の「アプリセンター → 手動インストール」からインストールします。

- **fnOS 統一ゲートウェイに対応**：デスクトップのアイコンをクリックすると、管理画面が `/app/gately/` で開き、fnOS と同じアクセス入口を共用します。LAN のアドレスでも fnOS のリモートドメインでも使え、16680 ポートを開放・転送する必要はありません。ゲートウェイ経由のアクセスは fnOS が制御し、fnOS 管理者だけが開けます。
- **fnOS 管理者は fnOS のログイン状態でログイン**：「設定 → アクセス制御」で「fnOS のログイン状態で自動ログイン」を有効にすると、fnOS にログイン済みの管理者はパスワードや 2 段階認証コードなしでそのまま Gately に入れます。一般の fnOS ユーザーは引き続きログインが必要です。ログアウトした後は自動で再ログインせず、ログイン画面に「fnOS アカウント &lt;ユーザー名&gt; でログイン」ボタンが表示されます。この設定は既定で無効です。
- **すべての機能を利用可能**：アプリは root で動作するため、80/443 の待ち受け、Docker の管理、Web ターミナルが使えます。設定はアンインストール時も保持され、アップグレードは新しい `.fpk` をインストールするだけです。

詳しくは [インストールとデプロイ · fnOS ネイティブアプリ](/ja/docs/guide/install#fnos) を参照してください。

## 機能モジュールのスイッチ

「設定 → 機能モジュール」でモジュール全体を無効にできます。無効にしたモジュールは設定を読み込むだけで、サービスを起動せず、管理 API も提供せず（エンドポイントは 403 を返します）、画面からも非表示になります。設定は保持され、再度有効にすると元に戻ります。他のモジュールが依存しているモジュールは無効にできず、変更は再起動後に反映されます。一部の機能しか使わない場合は、待ち受けるサービスと呼び出せるエンドポイントを減らせます。

## その他の改善

- 管理画面の文言を言語ごとに 1 ファイルにまとめ、初回読み込み時のリクエスト数を約 170 から約 75 に減らしました。遅延読み込みするページやスタイルシートの読み込みに失敗した場合は、1 回だけ自動で再読み込みします。
- API ドキュメントに、機能モジュールのスイッチと fnOS 関連の設定フィールドの説明を追加しました。

## アップグレード

- Docker：新しいイメージを取得してコンテナを再作成します。バイナリ：実行ファイルを置き換えて再起動します。
- fnOS ネイティブアプリと Docker イメージはどちらも 16680 ポートを使います。Docker イメージからネイティブアプリに移行する前に、`gately` コンテナを停止し、設定ディレクトリをアプリの `var/config` にコピーしてください。
