# Gately v0.5.0 リリース

2026年10月19日

Gately はネットワークの境界で動作し、DNS の認証情報や証明書の秘密鍵を扱います。そのため「動作が見えること」を常に第一の原則にしてきました。v0.5.0 ではこの原則を「コードがオープンソースであること」から「実行時の動作を追跡できること」へ広げました。誰がいつ何を変更したか、設定がどう変わってきたか、ダウンロードしたバイナリが本当に公式ビルドかを確認できます。

[v0.5.0 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.0)

## 追跡可能性：監査ログと設定履歴

- **監査ログ**：ログイン、すべての設定変更、バックアップや秘密鍵のダウンロード、ターミナルセッションを、ユーザー、送信元 IP、メソッド、パスとともに記録します。リクエストボディやシークレットは保存しません。
- **設定履歴とワンクリックのロールバック**：設定ファイルを上書きするたびに直前のバージョンを保存します（ファイルごとに 30 件保持）。1 行ずつ比較してロールバックでき、ロールバック自体も取り消せます。
- **実際のクライアントアドレス**：管理画面を同じホスト上の nginx、haproxy、Gately の Web サービスの背後に置いた場合、転送されたアドレスはローカルのプロキシからのものだけを信頼します。これにより「LAN 内からのみ許可」、ログインのレート制限、監査ログのいずれも実際の訪問者を把握できます。

詳しくは [監査ログと設定履歴](/ja/docs/guide/audit) を参照してください。

## より安全なログイン

- **Passkey ログイン**：パスワードの代わりに指紋、顔認証、デバイスの PIN を使います。保存するのは公開鍵だけで、認証コードの入力も不要です。
- **読み取り専用アカウント**：家族や同僚に閲覧専用のアカウントを渡せます。設定の変更、バックアップのダウンロード、シークレットの読み取りはできません。
- **署名付きリリース**：バイナリと Docker イメージには cosign の署名、ビルドの来歴証明、SBOM が付属し、公式 CI でビルドされたものか確認できます。[リリースの検証](/ja/docs/guide/verify) を参照してください。

## 新機能

- **ACME HTTP-01**：対応する DNS プロバイダーがなくても証明書を発行できます。
- **HTTP/3（QUIC）**：Web サービスのリスナーでスイッチ 1 つで有効にできます。
- **ポート転送からの PROXY プロトコル送信**：haproxy や nginx を何段か経由しても、実際のクライアントアドレスを保持できます。[ポート転送](/ja/docs/modules/portforward) を参照してください。
- **DDNS プロバイダーを 7 つ追加**：Amazon Route 53、OVHcloud、Gandi、NS1、Bunny DNS、Namecheap、DynDNS2（No-IP、Dynu など）。
- **通知チャネルを 7 つ追加**：ntfy、Gotify、Pushover、Discord、Slack、ServerChan、PushPlus。「重大な障害」「証明書の期限」「セキュリティとログイン」などのルールテンプレートも内蔵しました。

## 運用をより簡単に

- **全体の Prometheus エンドポイント** `/api/metrics`：証明書の有効期限、DDNS の同期状態、ポート転送のトラフィック、サイトとバックエンドの健全性を 1 回のスクレイプで取得でき、Grafana ダッシュボードも用意しています。[監視メトリクス](/ja/docs/reference/monitoring) を参照してください。
- **ネットワーク自己診断**：公開 IPv4 / IPv6、キャリアグレード NAT、システム時刻、80 / 443 番ポート、DDNS の名前解決、証明書の有効期限をワンクリックで確認できます。
- **初回起動ガイド**：パスワードの変更、2 段階認証または Passkey の設定、自己診断、Lucky からのインポート、通知の設定を 1 ページで済ませられます。
- **デプロイ**：`GATELY_INITIAL_PASSWORD` で初期パスワードを指定でき、`-apply` による宣言的な設定ディレクトリは GitOps に向いています。systemd と OpenWrt のサービステンプレートも同梱しました。[インストールとデプロイ](/ja/docs/guide/install) を参照してください。

## アップグレード時の注意

- Docker：新しいイメージを取得してコンテナを再作成します。バイナリ：実行ファイルを置き換えて再起動します。
- ポート転送ルールで PROXY プロトコルを送信する場合、転送先（たとえば haproxy の `accept-proxy`）がそれを受け付ける必要があります。v0.4.x にダウングレードする前に、まず転送先の PROXY 設定を外してください。
- ローカルのプロキシを信頼する設定は既定で有効で、「設定 → アクセス制御」で無効にできます。
- QUIC 対応により、単一バイナリのサイズは約 32 MB になりました。
