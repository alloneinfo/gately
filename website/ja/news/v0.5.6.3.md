# Gately v0.5.6.3 リリース

2026年10月23日

v0.5.6 系の修正リリースで、主に OpenWrt、ImmortalWrt、iStoreOS などのルーター向けです。その他のデプロイ方法は必要に応じてアップグレードしてください。

[v0.5.6.3 をダウンロード](/ja/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.3)

## 概要に OpenWrt の br-lan を表示

概要は Docker などの仮想インターフェースを非表示にしますが、ルールの `br-` プレフィックスが OpenWrt の LAN ブリッジ `br-lan` まで隠していました。サブルーター構成では LAN の IPv4 とグローバル IPv6 がどちらも `br-lan` にあるため、概要にアドレスが一つも表示されませんでした。現在は Docker のカスタムネットワークのブリッジ（`br-` と 16 進数 12 桁）だけを隠し、`br-lan`、`br-wan` は表示されます。DDNS と STUN でインターフェースからアドレスを取得する場合は、以前から `br-lan` を選択できます。

## OpenWrt でシステムのタイムゾーンを使用

OpenWrt には `/etc/localtime` も `/usr/share/zoneinfo` もなく、procd はサービス起動時に `TZ` を渡しません。そのため Gately は常に UTC で動作し、ログや通知の時刻が数時間ずれ、設定で `Asia/Shanghai` などを指定しても無効と表示されていました。現在はタイムゾーンデータを内蔵し、設定のタイムゾーンはすべて保存できます。指定がない場合はシステムに設定されたタイムゾーン（`/etc/config/system` の `zonename`、なければ `/etc/TZ`）を使い、LuCI の設定と一致します。

## アップグレードについて

- OpenWrt パッケージ：新しい `.apk` または `.ipk` を上書きインストールするか、「システム設定」で更新を確認してください。
- 時刻を直すために入れた `zoneinfo-*` パッケージは残しても削除しても構いません。
- LuCI でシステムのタイムゾーンを変えた後は Gately の再起動が必要です。Gately の設定で指定したタイムゾーンがシステムより優先されます。
