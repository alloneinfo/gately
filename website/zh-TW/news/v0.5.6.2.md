# Gately v0.5.6.2 發布

2026 年 10 月 23 日

這是 v0.5.6 系列的修復版本，所有部署方式都建議升級。

[下載 v0.5.6.2](/zh-TW/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.6.2)

## Docker 29 下可以正常管理容器

Docker 25 起逐步提高支援的最低 API 版本，Docker 29 要求至少 1.44，而 Gately 固定使用 1.41，Docker 管理頁因此提示無法連線。現在 Gately 首次連線時讀取 Docker 的版本範圍：支援 1.41 時繼續使用 1.41，不支援時改用 Docker 的最低版本，20.10 之前的舊版 Docker 則使用其自身版本。

## 未登入時直接進入登入頁

工作階段保存在瀏覽器無法讀取的 Cookie 中，之前未登入開啟管理介面會先渲染總覽頁，等介面回傳 401 才跳到登入頁，出現一閃而過的主畫面。現在進入頁面前先確認登入狀態，未登入時直接顯示登入頁，登入後回到原本要開啟的頁面。

## Cloudflare 相容 Lucky 匯入的設定

Lucky 的 Cloudflare 只使用 API Token，匯入的設定裡「ID」欄位常殘留其他服務商的 AccessKey，Gately 把它當作帳號信箱改用 Global API Key 認證，DDNS 與憑證驗證因此報錯 6003 Invalid request headers。現在只有 ID 是信箱時才使用 Global API Key，其餘情況按 API Token 認證。

## DDNS 紀錄改名後立即同步

修改任務時，改了網域、類型、線路或 TTL 的紀錄會沿用改名前的同步狀態，被當作已同步而不建立新的解析。現在這些紀錄會在儲存後重新同步。

## Web 服務登入頁與錯誤頁重新設計

開啟網頁認證的網站登入頁、404 與 502 錯誤頁，以及管理後台輸錯安全入口時的提示頁，換成統一的卡片式設計，隨系統自動切換淺色與深色。兩步驟驗證改為彈窗：輸入使用者名稱和密碼後，需要動態驗證碼時在原頁面彈出驗證碼框，輸滿 6 位自動送出；之前需要驗證碼時會清空已填的使用者名稱和密碼，現在不必重新輸入，密碼輸錯時也會保留使用者名稱。命令列、API 等非瀏覽器請求仍回傳原來的純文字。

## 升級提示

- Docker 拉取新映像後重建容器；其他部署方式可在「系統設定」中線上升級，或下載對應安裝包覆蓋安裝。
- 之前因 6003 報錯手動清空過 Cloudflare ID 的任務無需改回。
