# Gately v0.5.9.1 發布

2026 年 10 月 26 日

這是 v0.5.9 系列的更新，來自 [issue #25](https://github.com/wangwanjie/gately/issues/25) 的建議，並修復了兩處編輯後無法儲存的問題。

[下載 v0.5.9.1](/zh-TW/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.9.1)

## HTTP 與 HTTPS 共用同一埠

開啟 HTTPS 的監聽新增「同埠 HTTP」選項，預設「不接受」。選「跳轉到 HTTPS」時，存取 `http://網域:埠` 會跳轉到 `https://網域:埠`（GET、HEAD 用 301，其他方法用 308，保留請求方法與請求本文）；選「直接服務」時以明文 HTTP 提供站台。適合只能映射一個埠、又希望訪客輸錯協定也能開啟的情境，例如家用寬頻的非標準埠。

Gately 依每個連線的第一個位元組區分 TLS 與 HTTP，PROXY 協定標頭仍先於協定識別解析，HTTP/2 協商、ACME HTTP-01 驗證照常運作，`Alt-Svc` 只在 HTTPS 回應中傳送。匯入 nginx 設定時，HTTPS server 中的 `error_page 497 https://$host:$server_port$request_uri` 會轉換為「跳轉到 HTTPS」。詳見 [Web 服務](/zh-TW/docs/modules/web)。

## File Browser 存取位址

File Browser 實例可以填寫多個存取位址，例如經 Web 服務反向代理的 `https://files.example.com/`，實例卡片顯示這些位址，留空時仍依監聽位址與埠推測。第一個位址的協定、主機與埠寫入 File Browser 的外部位址，分享連結使用該位址。詳見 [檔案服務](/zh-TW/docs/modules/tools#filebrowser)。

## 修復

- 編輯已有的 File Browser 實例後儲存提示 `json: unknown field "state"`，現已修復。
- 編輯已有的 Cloudflare 隧道後儲存同樣提示 `json: unknown field "state"`，現已修復。
- 開啟共用使用者後，FTP 與 WebDAV 的監聽日誌把使用者數顯示為 0（[issue #26](https://github.com/wangwanjie/gately/issues/26)）。現在與 SMB 一樣顯示「N 個使用者，其中 M 個共用使用者」，WebDAV 在共用使用者變化後會記錄新的數量。

## 升級提示

- 「同埠 HTTP」預設關閉，升級後已有監聽的行為不變；修改此項會重新啟動該監聽，已有連線會中斷。
- 「直接服務」下站台經明文 HTTP 存取時不加密，網頁認證、共用使用者登入等密碼也以明文傳輸，公網存取建議用「跳轉到 HTTPS」。
