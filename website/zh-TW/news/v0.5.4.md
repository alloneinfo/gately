# Gately v0.5.4 發布

2026 年 10 月 21 日

這一版解決「怎麼裝、怎麼升級」。systemd、PVE LXC 容器、手動部署的 OpenWrt 等 Linux 執行檔部署，現在可以在管理介面裡直接升級；OpenWrt 與 iStoreOS 使用者可以用系統內建的套件管理員安裝 Gately。

[下載 v0.5.4](/zh-TW/download) · [GitHub Release](https://github.com/wangwanjie/gately/releases/tag/v0.5.4)

## 線上升級

在「關於」頁點擊「檢查更新」，會彈出新版本的版本號、發布日期與更新內容，點擊「立即升級」後 Gately 依序：

1. 從 GitHub 下載與本機平台對應的發布包；
2. 對照同一版本的 `checksums.txt` 驗證 SHA-256；
3. 試執行新程式，確認能在本機執行；
4. 替換執行檔並原地重新啟動，舊版本保留為同目錄下的 `gately.old`，便於回退。

彈出視窗裡即時顯示目前步驟、下載進度與速度，替換程式之前可以隨時取消；重新整理頁面後會接著顯示仍在進行的升級，失敗時顯示原因並可重試。

- **PVE LXC 容器**：用 OCI 映像檔建立的 LXC 容器同樣可以線上升級，不用再刪除容器重建；
- **更新代理**：存取 GitHub 不穩定時，可以在「關於」頁或「設定 → 網路與執行」設定 http、https 或 socks5 代理，檢查更新與下載都會經過它；
- **離線升級與回退**：「上傳升級包」接受發布頁的 tar.gz 或解壓縮後的程式，不限版本高低，也能用來回退；
- **只由管理員手動觸發**：Gately 不會自動下載或安裝任何版本。Docker、飛牛 fnOS 與 OpenWrt 安裝包會提示各自的升級方式。

詳見 [安裝部署 · 線上升級](/zh-TW/docs/guide/install#online-upgrade)。

## OpenWrt 安裝包

每個版本附帶 OpenWrt 安裝包，架構有 amd64 / arm64 / arm / mipsle / mips / riscv64：

- OpenWrt 24.10 及更早版本（含 iStoreOS）：`opkg install ./gately_v0.5.4_openwrt_<架構>.ipk`
- OpenWrt 25.12 起：`apk add --allow-untrusted ./gately_v0.5.4_openwrt_<架構>.apk`

安裝後自動啟用開機自動啟動並啟動服務，管理介面在 `http://<路由器位址>:16680`。設定儲存在 `/etc/gately`，升級、解除安裝與刷寫韌體時都會保留；升級時安裝新版安裝包即可。安裝前會核對裝置架構，請依 `/etc/openwrt_release` 中的 `DISTRIB_ARCH` 選擇安裝包。程式約 35 MB，適合 x86 軟路由、ARM64 盒子等儲存空間較大的裝置。

詳見 [安裝部署 · OpenWrt](/zh-TW/docs/guide/install#openwrt)。

## 問題修正

- 透過 Gately 自身轉發存取管理介面時，儲存設定不再中斷連線：編輯連接埠轉發規則時，只要監聽連接埠、協定、模式與限制不變，就原地更新目標與 SNI 分流並保留現有連線；儲存連接埠轉發或 Web 服務設定也不再重新啟動全部監聽。
- WAF 不再把 `credentials`、`forwardAuth` 這類 JSON 欄位名稱誤判為系統檔案存取，儲存 DDNS 任務或新增 Web 服務監聽時不再回傳 403。
- 網域、IP 清單、請求標頭、STUN 伺服器等清單輸入框不再吞掉 Enter、逗號與空格。
- mips / mipsle 程式改為軟體浮點編譯，可以在沒有硬體浮點運算單元的路由器上執行。
- 版本比較改為語意化版本，較新的建置不會再被提示「升級」到舊版本。

## 升級提示

- 線上升級從 v0.5.4 開始提供，這一次仍需手動升級：執行檔替換後重新啟動，Docker 拉取新映像檔後重建容器，飛牛在應用中心安裝新版 `.fpk`。之後的版本就可以在「關於」頁直接升級。
- 之前手動部署在 OpenWrt 上的，可以直接安裝 `.ipk` / `.apk` 覆蓋，`/etc/gately` 中的設定會繼續使用。
