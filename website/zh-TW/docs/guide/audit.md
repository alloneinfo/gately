# 稽核與設定歷史

Gately 掌握 DNS 金鑰與憑證私鑰，所以誰在何時做了什麼、設定如何變化，都應當可以追查和撤銷。

## 操作稽核

側邊欄「系統 → 操作稽核」列出以下操作，依時間倒序排列，可依類別篩選或依路徑、使用者、IP 搜尋：

| 類別 | 記錄內容 |
| --- | --- |
| 登入 | 密碼、Passkey 與第三方登入的成功和失敗，以及登出 |
| 變更 | 管理後台與 API 權杖發起的所有寫入操作（新增、修改、刪除、啟停、還原等） |
| 敏感存取 | 下載設定備份、診斷包、憑證私鑰，開啟 Web 終端機或容器終端機等 |

每筆記錄包含時間、操作者（使用者名稱或 `api-token:<權杖名稱>`）、來源 IP、方法、路徑與狀態碼。**不記錄請求內容與任何金鑰**。

- 日誌寫入設定目錄下的 `audit.log`（JSON Lines），單一檔案超過 5 MiB 後輪替，保留 3 份歷史；
- 管理介面放在本機反向代理之後時，記錄的是真實來源，並另外標註經過的代理位址，原理見 [安全模型](/zh-TW/docs/guide/security)；
- 變更與敏感存取會作為 `audit.change`、`audit.access` 事件發出，可在 [通知中心](/zh-TW/docs/modules/notify) 用「設定變更」「安全與登入」範本推送；
- 唯讀帳號與 API 權杖無法檢視稽核日誌。

## 設定歷史與還原

每次覆寫設定檔之前，Gately 會把舊內容保存為一個歷史版本，位於設定目錄的 `history/<名稱>/`，每個設定保留最近 30 個。`account.json`（帳號憑據）與 `tokens.json`（權杖）不記錄歷史。

在「系統 → 設定歷史」中：

1. 選擇設定檔，檢視各歷史版本的保存時間與大小；
2. 點擊「比較」檢視該版本與目前設定的逐行差異；
3. 點擊「還原」恢復該版本，Gately 隨後自動重新啟動使其生效。

還原前的目前內容也會保存為新的歷史版本，因此還原本身可以再次撤銷。
