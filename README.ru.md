# Gately

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-TW.md) | [日本語](README.ja.md) | [한국어](README.ko.md) | [Español](README.es.md) | [Français](README.fr.md) | [Deutsch](README.de.md) | **Русский** | [Português (Brasil)](README.pt-BR.md)

Открытый, поддающийся аудиту набор инструментов сетевого шлюза для домашней сети, NAS, облачных хостов и любых серверов. Вдохновлён [Lucky](https://github.com/gdy666/lucky) и предоставляет аналогичные возможности с полностью открытым исходным кодом. DDNS, STUN-обход NAT, проброс портов, обратный прокси, сертификаты, WAF и другие востребованные функции собраны в одном файле размером около 22 МБ, а конфигурацию Lucky можно импортировать в один клик.

## Зачем нужен Gately

Lucky хорошо знаком пользователям NAS и домашних сетей в Китае: он объединяет DDNS, STUN-обход NAT, обратный прокси и другие функции и подсказал идеи для продукта Gately — без Lucky не было бы и Gately. Lucky распространяется бесплатно, но с закрытым исходным кодом; Gately полностью открыт, поэтому пользователи и сообщество могут напрямую изучать исходный код и конфигурацию. Программа, которая работает на границе сети и хранит ключи DNS и закрытые ключи сертификатов, должна быть прозрачной, и открытый код позволяет увидеть, что именно она делает. Обязательства Gately:

- Исходный код открыт под лицензией Apache-2.0 и доступен для проверки сообществом
- По умолчанию нет подключений к серверам проекта и отправки данных об устройстве; вход через сторонние сервисы использует ваши собственные OAuth-приложения без посредников
- Все внешние адреса (определение публичного IP, STUN-серверы и т. д.) видны, изменяемы и отключаемы
- Конфигурация хранится в обычном JSON, её можно вести в git для аудита и отката

## Быстрый старт

### Docker

Образ поддерживает amd64, arm64 и arm/v7:

```bash
docker run -d --name gately --network host \
  -v ./gately-data:/etc/gately \
  -v /var/run/docker.sock:/var/run/docker.sock \
  ghcr.io/wangwanjie/gately:latest
docker logs gately 2>&1 | grep -i "initial password"
```

Откройте `http://<IP устройства>:16680`, войдите с логином `admin` и начальным паролем из журнала, затем в разделе «Настройки» смените пароль и включите двухфакторную аутентификацию. Полный пример Compose см. в [deploy/docker-compose.yml](deploy/docker-compose.yml).

Проброс портов, STUN и веб-службам нужно слушать порты хоста, поэтому рекомендуется `--network host`. Если управление Docker не требуется, монтирование `docker.sock` можно убрать.

### Бинарный файл

Скачайте архив для своей платформы из [Releases](https://github.com/wangwanjie/gately/releases) (Linux amd64/arm64/arm/mips/mipsle/riscv64, macOS, Windows, FreeBSD), распакуйте и запустите:

```bash
./gately -c /etc/gately
```

Параметры: `-c` — каталог конфигурации (можно также задать переменной окружения `GATELY_CONFIG_DIR`), `-listen` переопределяет адрес, на котором слушает интерфейс управления, `-version` выводит версию.

### Вызовы API

На странице «API-токены» панели управления создайте токен (можно создать несколько, для каждого модуля отдельно выдаются права только на чтение или на чтение и запись, можно задать срок действия; открытое значение показывается только один раз после создания) — и скрипты смогут массово обращаться к API управления:

```bash
curl -H "Authorization: Bearer gtl_xxxx" http://localhost:16680/api/ddns/tasks
```

Учётная запись, двухфакторная аутентификация, управление токенами, а также интерфейсы резервного копирования, восстановления, перезапуска и системных настроек доступны только из сеанса входа. Все интерфейсы, необходимые права и структуры данных описаны на странице «Документация API» панели управления; их также можно экспортировать командой `make api-docs` в [docs/api](docs/api/ru) (`openapi.json` и `API.md`), на которые сайт https://gately.cn ссылается напрямую при публикации.

При обновлении со старой версии прежний глобальный API-токен автоматически становится «старым» токеном (значение сохраняется, права на все модули). Рекомендуется сузить его права на странице «API-токены» или заменить новым токеном.

### Tailscale, frp, cloudflared

Эти три модуля управляют официальными внешними программами (автоматический перезапуск, логи собираются в интерфейсе). Сам Gately их не содержит, поэтому всегда можно использовать последнюю версию из upstream. Программы ищутся в таком порядке: путь, указанный в настройках модуля, `PATH`, подкаталог `bin/` каталога конфигурации. При развёртывании в Docker положите бинарный файл в смонтированный каталог конфигурации, например `./gately-data/bin/frpc`; для Tailscale нужно предоставить и `tailscale`, и `tailscaled`. Токены и ключи в файлах конфигурации хранятся с правами 0600, токен cloudflared передаётся через переменную окружения и не попадает в список процессов.

### Миграция с Lucky

См. [руководство по миграции](https://gately.cn/ru/docs/guide/migration). Кратко: в разделе «Настройки → Импорт из Lucky» выберите файл `lucky_*.lkcf` из каталога конфигурации Lucky, просмотрите предварительный результат и импортируйте. Импортированные правила по умолчанию отключены: отключайте модули в Lucky и включайте их в Gately по одному.

## Разработка

Зависимости: Go 1.26+, Node.js 24+, pnpm.

```bash
make web      # сборка фронтенда (вывод в web/dist, встраивается через go:embed)
make build    # сборка bin/gately
make test     # go test -race ./...
make lint     # gofmt, go vet, проверка типов фронтенда
```

Для разработки фронтенда запустите `cd web && pnpm dev`; `/api` проксируется на локальный `127.0.0.1:16680`.

Некоторые тесты по умолчанию пропускаются и требуют дополнительных условий:

| Тест | Как включить |
| --- | --- |
| Сквозной тест ACME (Pebble) | Установите pebble и pebble-challtestsrv, задайте `GATELY_PEBBLE_BIN` и `GATELY_PEBBLE_SRC` (в CI запускается автоматически) |
| Реальные публичные STUN-серверы | `GATELY_NET_TEST=1` |
| Проверка импорта на реальной конфигурации Lucky | `GATELY_LUCKY_SAMPLE` и др., см. `TestImportRealSample` в соответствующих модулях |

Структура каталогов и выбор технологий описаны в [docs/ROADMAP.md](docs/ROADMAP.md).

Исходный код сайта ([gately.cn](https://gately.cn)) находится в `website/` и основан на VitePress: `cd website && pnpm install && pnpm dev`; `pnpm deploy:site` собирает сайт и синхронизирует его с сервером.

## Правила участия

- Совместимость с Lucky основана на публично наблюдаемом поведении, интерфейсах и форматах конфигурации. Не отправляйте код, скопированный из бинарных файлов или фронтенд-артефактов Lucky.
- Новому модулю нужны: структура конфигурации и валидация, запуск и остановка во время работы, REST-интерфейс, модульные тесты; модули, которые можно перенести из Lucky, реализуют `luckyimport.Importer`, а модули, статус которых нужно показывать на странице обзора, — `module.Summarizer`.
- Комментарии в коде пишутся на китайском языке; управляющие конструкции обязательно оформляются с фигурными скобками.
